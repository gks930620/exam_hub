## 제품 개요

- **무엇을 만드나**: 큐넷 등 각종 시험일정을 한곳에 모아 보여주고, 관심 시험의 D-day와 원서접수 시작/마감을 알려주는 **웹 서비스**.
- **⚠️ 범위: 웹 전용 + CSR(React).** 모바일 앱(Flutter) 안 함(`flutter_common/` **삭제됨**). 인터랙티브 기능(시험 검색·내 시험 등록·알림설정)이 전부 **React CSR 웹**에서 동작한다.
- **사용자는 누구인가**: 취준생·자격증 준비생·자격 수당이 필요한 직장인 — "접수 기간을 놓치면 다음 회차까지 반년 대기"가 페인 포인트.
- **알림 채널**: **이메일 실발송 중**(2026-08-10 확정, `EmailNotificationSender`, `MAIL_ENABLED=true`). 알림톡은 사업자등록 전이라 `ALIMTALK_ENABLED=false` 로 꺼 둠. 웹 푸시는 미구현. `LogNotificationSender` 는 발송 체인의 마지막 폴백일 뿐이다.
- **방향 전환(v1.1)**: 큐넷 국가기술자격 → **각종 시험 통합**(완료 — 시험 마스터 870종·공개 841, 일정 없어도 노출). 유료화 제거 방향, 계정·커뮤니티 도입 확정. `작업자_AI_문서/시험데이터/02_전수목록.md`·`08_계정과_커뮤니티.md` 참고.

이 프로젝트만의 특이사항:

- **인증**: 소셜 로그인(카카오·구글 OAuth2) → `Member` + JWT(`Authorization: Bearer`). 매니저(운영자)만 `/manager/login` 폼 로그인. 구 `X-Device-Id` 기기식별은 **폐기·전환 완료**. 설계는 `08_계정과_커뮤니티.md`.
- **DB**: 로컬 = **인메모리 H2**(`jdbc:h2:mem:examhub`, MODE=MySQL, ddl-auto=create) / 운영 = Railway MySQL (env 미설정 시 fail-fast).
  - **기동할 때마다 비우고 `seed_exams.sql` 로 다시 채운다** — 컨벤션 §5-2 그대로다. 따로 초기화할 게 없다.
  - 한동안 파일 H2 였다(2026-09-01 ~ 2026-11-13). 적재가 느려서 피했던 건데, 느린 원인이 INSERT 가
    아니라 **수집 파이프라인(레코드당 쿼리 14.5개)과 SQL 로깅(91만 줄·25MB)** 이었다. 그걸 고치니
    **전체 기동 23초**가 되어 원칙으로 돌아왔다(2026-11-13 사용자 결정·실측).
  - SQL 로그는 기본 꺼져 있다. 볼 때만 `--logging.level.org.hibernate.SQL=debug`.
- **외부 연동 상태**: `QnetApiScheduleSource`(큐넷 실 API)는 **실호출 검증 완료**(2026-08-28 전량 613콜). 발송은 **이메일 실발송**(`EmailNotificationSender`). 로컬도 `.env` 의 `QNET_API_ENABLED=true` 로 실 API 를 쓰되 **기동 때는 수집하지 않고**(`collect.on-startup` 기본 false) `seed_exams.sql` 시드로 복원한다. 실 수집은 05:00 배치. 스크래퍼 8곳(상의·KCA·Kdata·토익·텝스·JLPT·국시원·TOPIK)은 `SCRAPE_ENABLED` 기본 **on**.
- **각종 시험 통합**: 비큐넷 시험도 `seed_exams.sql` 에 같이 들어 있다(그중 50종은 `provenance=approx` 추정치 — 화면에 "시행처 확인 필요"로 표시된다). `Certificate.category`로 분류.
- **시드는 SQL 하나다** — `seed_exams.sql`(18,607행: 시험 870·일정 2,948·알림예약 14,739·상세 50).
  **기동 때 JSON 을 읽는 경로는 없다**(2026-11-14 — 시드 JSON 6개와 로더 4개를 들어냈다).
  - 넣는 주체는 `SqlSeedRunner` 하나. **시험 표가 비었을 때만** 돈다 →
    로컬(인메모리)은 매 기동, 운영은 첫 배포 때 한 번. 두 번째 배포부터는 수집한 일정을 안 덮는다.
    톰캣이 열리기 전(`ContextRefreshedEvent`)에 끝나므로 빈 화면이 노출되지 않는다. **적재 1.8초.**
  - H2·MySQL 양쪽에서 돌아야 해서 H2 전용 문법을 안 쓴다(한글은 평문, 자동증가 카운터는 러너가 맞춘다).
  - `data.sql` 은 **매니저 계정만** 넣는다(로컬 always / 운영 never).
  - 다시 만들기: `scripts/make_seed_sql.cjs`. `LocalSeedSqlTest` 가 행 수를 지킨다 — 바뀌면 같이 고친다.
  - 테스트는 `seed.from-sql=false`(기본)라 데모 10종 픽스처를 쓴다. 시드가 필요한 테스트 넷만
    `true` + **자기 DB 이름**을 쓴다(다 같은 `testdb` 를 create-drop 으로 공유해서 서로 지운다).
- 시각은 전부 KST — `TimeUtil`(Asia/Seoul) 경유.

```
product-planner(사용자 흐름·인수 조건) → designer(화면 정의서)

→ devops(커밋·배포)
```

## 작업 방식 (TDD — 이 프로젝트의 핵심 규칙)

**항상 TDD다. 프로덕션 코드보다 테스트 코드가 먼저다. 예외 없음.**

1. **테스트가 명세다** — senior-dev가 API 계약·화면 요구를 테스트 코드로 먼저 작성한다(실패 상태 = Red). 테스트 없이 개발자에게 일을 넘기지 않는다.
2. **개발자는 테스트를 통과시킨다(Green)** — senior-dev의 테스트 수정 금지. 테스트가 틀렸다고 판단되면 senior-dev에게 되돌린다.
3. **테스트에 없는 코드가 필요해지면** — 계약·공개 동작은 senior-dev에게 테스트 추가를 요청하고, 내부 구현 세부는 개발자가 직접 테스트를 먼저 작성(실패 확인)한 뒤 구현한다. 어떤 경우에도 순서는 테스트 → 코드다.
4. **계약 밖 변경 금지** — API 응답 필드를 임의로 추가/변경하면 다른 스택이 깨진다. 계약 변경은 senior-dev를 통해서만.
5. **`qa` 에이전트 통과가 완료 조건** — 개발자 테스트를 재실행하는 게 아니라, 기획서로 테스트 케이스를 설계해 **도는 제품의 API 를** 시험하는 독립 관문이다. 테스트 없이 들어온 프로덕션 코드는 여기서 결함으로 잡힌다.

## ⚠️ 말을 가른다: "테스트"와 "QA" (2026-11-14 사용자 지시)

| 말 | 누가 | 무엇 |
|---|---|---|
| **테스트** | 🤖 작업자 | `./gradlew test`·`npm test` + `qa` 에이전트가 API 를 두드려 보는 것 **전부** |
| **QA** | 👤 사용자 | **5101(Vite dev)에서 실제 화면을 보고** 하는 것 |

- `qa` 라는 에이전트 이름에 속지 말 것 — **하는 일은 테스트다.** 브라우저가 없어서
  레이아웃 깨짐·다크모드·모바일 폭·클릭 흐름은 **구조적으로 못 잡는다.**
- 그래서 작업자는 **"QA 통과"라고 쓰지 않는다.** "테스트 통과"까지만 말하고,
  **화면 검증이 남았다는 것을 분명히** 하고 사용자가 볼 지점을 짚어 준다.

## 이 프로젝트의 규칙

- **커밋·푸시·배포는 사용자가 명시적으로 요청할 때만** — 실행은 devops 담당.
- **배포 전 조건**: 테스트 통과(자동) + **사용자의 화면 QA 통과**. 절차는 railway-deploy 스킬.
- **새 라이브러리 도입은 senior-dev 결정 사항** — 개발자가 임의로 추가하지 않는다.
- **코드 컨벤션**: `code-convention` 스킬이 기준이다 (DTO class 규칙, 계층 구조, 백엔드 테스트는 컨트롤러 통합테스트만 등). 문서와 코드가 어긋나면 문서에 맞춰 코드를 고친다. DTO 는 전부 `class`(Lombok)로 통일했다(2026-09-21) — 요청 DTO 에는 `@Setter` 가 있어야 Jackson 이 값을 채운다.
- **금지**: 요청받지 않은 대규모 리팩터링, 자기 영역 밖 스택의 코드 수정.
