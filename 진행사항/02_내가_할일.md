## 🟡 2순위 — 소셜 로그인 키 (카카오 ✅ / 구글 🟡)

**왜**: 로그인 방식을 **소셜 단독**(카카오·구글)으로 정했다([08 설계서](../설계/설계문서/08_계정과_커뮤니티.md)).
자체 이메일/비밀번호 계정을 안 만들기로 했으므로, **키가 없으면 로컬에서도 로그인이 아예 안 된다.**

| 제공자 | 상태 | 남은 것 |
|---|---|---|
| **카카오** | ✅ 됨 | 없음. `/oauth2/authorization/kakao` → 카카오 인증 화면까지 실제로 확인함(2026-08-10) |
| **구글** | ✅ 켜짐 | `.env` 의 **`GOOGLE_CLIENT_SECRET`** 채워짐(2026-09-02). `oauth.yml` 은 그대로 |
| **JWT_SECRET** | ✅ 됨 | `.env` 에 48자 랜덤값 |

**키는 전부 `.env` 한 곳에 있습니다.** `oauth.yml` 에는 구조만 있고 `${KAKAO_CLIENT_ID}` 처럼 참조만 합니다 —
비밀값이 두 파일에 흩어져 있으면 어디를 고쳐야 하는지 헷갈리기 때문입니다.

구글 시크릿은 콘솔에서 **재발급받은 직후 화면에서만** 보이고 나중엔 다시 못 봅니다.
빈 값이어도 기동은 깨지지 않습니다 — `IncompleteSocialLoginRemover` 가 시크릿 없는 제공자만 걷어내고, 로그인 화면은 `/api/auth/providers` 로 설정된 제공자만 그립니다.
카카오로 로그인되니 급하진 않습니다.

**등록할 Redirect URI** (배포하면 그 도메인으로 하나씩 더 추가)
```
http://localhost:8081/login/oauth2/code/kakao
http://localhost:8081/login/oauth2/code/google
```

> ⚠️ **카카오 동의항목은 닉네임·프로필사진만** 켠다. `카카오계정(이메일)` 은 **비즈 앱 전환 전에는 켤 수 없고**,
> 켜지 않은 채 요청하면 **KOE205 로 로그인이 통째로 막힌다**(겪었다 → `oauth.yml` 에서 뺐다).
> 그래서 카카오 로그인은 이메일을 못 받고, 알림 받을 이메일은 **내 정보 화면에서 직접 입력**받는다.
> 자세한 건 [01_카카오_설정.md](../설계/운영/01_카카오_설정.md) §1-3.

#### 알아둘 것

- **발송 코드는 이미 검증 끝** — 가짜 SMTP 서버를 띄워 실제 전송·한글 인코딩·본문 링크까지 확인했습니다(`EmailSendingTest` 4건). 남은 건 자격증명뿐입니다.
- **AI 가 대신 못 하는 이유** — 앱 비밀번호는 사용자님 구글 계정에 2단계 인증으로 로그인해야 나오는 값입니다.
- 지메일은 **일 500통** 제한. 사용자가 늘면 AWS SES 로 옮기면 되고, 그때도 `.env` 의 `MAIL_HOST`·`MAIL_PORT`·계정만 바뀝니다.
- 받는 사람 주소는 **사용자가 내 정보 화면에서 직접 입력**합니다(`PUT /api/me/email`). 카카오가 이메일을 안 주기 때문입니다.
- 배포(Railway)할 때는 `.env` 가 안 올라가므로 **같은 4개 값을 Railway 환경변수에 다시** 넣어야 합니다.

## 🟡 4순위 — 배포 (Railway)

지금은 **미배포**다. 로컬에서만 돈다.

| # | 할 일 |
|:-:|---|
| 1 | Railway 가입 + 프로젝트 생성 |
| 2 | **MySQL 플러그인 추가** → 접속 정보 확인 |
| 3 | 환경변수 입력 (아래) |
| 4 | GitHub 저장소 연결 — **원격은 이미 있다**: `https://github.com/gks930620/exam_hub` (main) |

**넣어야 할 환경변수** — `.env` 와 `oauth.yml` 은 저장소에 안 올라가므로 **같은 값을 Railway 에 다시 넣는다.**

> **코드는 하나도 안 고쳐도 된다.** 아래 변수만 넣으면 로컬과 똑같이 돈다.
> 빠뜨리면 조용히 잘못 도는 것들(H2 로 떠서 데이터 소실 / 개발용 JWT 키 / localhost 링크)은
> `RailwayDeploymentValidator` 가 **기동을 중단시켜서** 알려 준다.

```
SPRING_PROFILES_ACTIVE=prod
SPRING_DATASOURCE_URL=jdbc:mysql://...
SPRING_DATASOURCE_USERNAME=...
SPRING_DATASOURCE_PASSWORD=...
JWT_SECRET_KEY=...              32자 이상. .env 것 재사용 말고 운영용을 새로
QNET_API_KEY=...                .env 에 있는 값
APP_PUBLIC_BASE_URL=https://내도메인    ← 알림 메일 속 링크 주소가 여기서 나온다
MAIL_ENABLED=true
MAIL_USERNAME=... / MAIL_PASSWORD=... / MAIL_FROM=...
```

**소셜 로그인**은 이름이 길다 — `oauth.yml` 이 없으니 스프링 표준 키 이름을 그대로 쓴다.
(provider URI 3종은 `application.yml` 에 있어서 **넣을 필요 없다.**)
```
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_KAKAO_CLIENT_ID=...
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_KAKAO_CLIENT_SECRET=...
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_KAKAO_CLIENT_AUTHENTICATION_METHOD=client_secret_post
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_KAKAO_AUTHORIZATION_GRANT_TYPE=authorization_code
SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_KAKAO_REDIRECT_URI={baseUrl}/login/oauth2/code/{registrationId}

# 매니저(운영자) 계정 — 로컬의 pass1234 를 그대로 올리면 기동이 중단된다(10자 이상)
MANAGER_USERNAME=...
MANAGER_PASSWORD=...
```
> 카카오는 grant-type·redirect-uri 까지 적어야 한다 — 스프링 내장 provider 가 아니라 기본값이 없다.
> 빠뜨리면 `authorizationGrantType cannot be null` 로 기동이 깨진다.
> 이 목록이 맞는지는 `DeployPortabilityTest` 가 검증한다(바뀌면 테스트도 같이 고칠 것).

> 카카오·구글 **Redirect URI 에 배포 도메인을 추가**하는 것도 잊지 말 것 — 로컬 것은 지우지 않는다.

### 매니저 계정 만드는 두 가지 길

**① 환경변수 (급할 때·비밀번호 분실 시)**
```
MANAGER_USERNAME=manager
MANAGER_PASSWORD=10자-이상-비밀번호
```
기동할 때 계정이 없으면 만들고, 있으면 비밀번호를 이 값으로 갱신한다.
**비밀번호를 잊었을 때 되찾는 유일한 길**이다. 로컬의 `pass1234` 를 그대로 올리면 기동이 중단된다.

평소에는 **비워 두는 것을 권한다** — 값이 남아 있으면 기동할 때마다 DB 의 비밀번호를 덮어써서,
DB 에서 바꾼 값이 다음 재기동에 되돌아간다.

**② 운영 DB 에 직접 INSERT (이 프로젝트의 기본)**

`MANAGER_USERNAME`/`MANAGER_PASSWORD` 를 **비워 두고** 직접 넣는다.
(로컬은 같은 일을 `data.sql` 이 대신한다 — 그 파일은 H2 일 때만 실행돼 운영에는 안 들어간다.)

먼저 해시를 만든다 — **평문을 넣으면 로그인이 안 된다**(로그인은 BCrypt 해시와 비교한다):
```powershell
./gradlew managerHash -Ppassword=내가정한비밀번호
# → {bcrypt}$2a$10$....  ← {bcrypt} 접두사까지 통째로 복사
```

그다음 INSERT:
```sql
INSERT INTO member
  (provider, provider_id, password_hash, nickname, role, status,
   notify_reg, notify_exam, notify_change, created_at, updated_at)
VALUES
  ('LOCAL', 'manager', '{bcrypt}$2a$10$여기에_위에서_찍은_해시',
   '매니저', 'ADMIN', 'ACTIVE', true, true, true, NOW(), NOW());
```

| 컬럼 | 왜 이 값인가 |
|---|---|
| `provider='LOCAL'` | 소셜이 아닌 자체 계정. 이게 아니면 폼 로그인이 계정을 못 찾는다 |
| `provider_id` | **로그인 아이디**가 된다. `(provider, provider_id)` 가 유니크 |
| `password_hash` | `{bcrypt}$2a$...` 통째로. 평문이면 로그인 실패 |
| `nickname` | **유니크 제약**이 있다. 이미 `매니저` 가 있으면 다른 이름으로 |
| `role='ADMIN'` | 이게 `USER` 면 로그인은 되는데 `/admin` 에서 403 |
| `status='ACTIVE'` | `WITHDRAWN` 이면 로그인이 거부된다 |
| `created_at`/`updated_at` | NOT NULL 이라 반드시 넣는다 |

> 확인: `/manager/login` 에서 로그인 → `/admin` 이 열리면 성공.
> 안 되면 `role` 과 `status` 부터 보세요.

### 시험 데이터는 자동으로 들어간다

`data.sql` 은 없어도 된다. **시험 마스터 870종은 기동 때 자동 적재**된다
(`CertificateMasterInitializer` — 이미 있는 종목은 건너뛰므로 재기동해도 안전).
매니저는 이 872종(공개 841) 위에 일정을 붙이는 것이다.

일정 있는 데모 시드(`ExamDataInitializer`·`SeedFileScheduleSource`)는 **운영에 안 들어간다** —
그건 추정 날짜가 섞인 개발용이라, 운영에는 큐넷 API·스크래퍼·매니저 수기입력으로만 채운다.

> `PORT` 는 Railway 가 자동으로 넣는다. 우리 설정이 그걸 따라간다.
> 배포는 **단일 서버**다 — 컨테이너 하나가 화면과 API 를 같이 서빙한다(Dockerfile 3단 빌드).
