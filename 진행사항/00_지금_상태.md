## 3. 실행 방법

**화면을 보거나 고칠 때(=QA 대부분)는 둘을 같이 띄운다.** 8101 은 한 번 띄워 두고, 화면은 5101 에서 본다.

```powershell
./gradlew bootRun                 # 8101 — API 담당. 한 번 띄워 두고 그대로 둔다
cd frontend; npm run dev          # 5101 — 화면. 저장 즉시 반영(HMR)
```
- **디자인·배치를 고칠 때 8101 을 껐다 켜지 않는다.** Vite 가 `/api`·`/oauth2` 를 8101 로 프록시한다
  (`frontend/vite.config.ts`). 재기동은 20~60초씩 걸리는데 QA 는 대부분 화면 수정이라 그게 다 낭비다.
- ⚠️ **5101 이 이미 점유돼 있으면 Vite 가 조용히 5102 로 뜬다.** 낡은 인스턴스가 다른 백엔드로
  프록시해 401 이 나올 수 있다 — 뜰 때 찍히는 포트를 확인하고, 낡은 것은 정리한 뒤 5101 에 띄운다.
- ⚠️ **bootRun 이 떠 있는 채로 `gradlew test` 를 돌리지 않는다.** 클래스가 잠깐 지워지며
  devtools 가 빈이 빠진 상태로 재기동해 시드가 잘못 돈다(2026-09-08 실측 — 추정치 18건이 되살아났다).
  테스트 전에 java 를 내리고, 끝나면 다시 띄운다.

```powershell
# 배포 번들 그대로 확인할 때만 (Gradle 이 프런트를 빌드해 넣는다)
./gradlew bootRun                 # http://localhost:8101 에서 화면까지

# 기동하면서 실 수집까지(큐넷 613콜 — 하루 한도 1,000, 평소엔 하지 말 것)
./gradlew bootRun --args="--collect.on-startup=true"
```
- 확인: `/healthz` → `{"status":"UP"}` · `/api/certificates/browse` → 공개 시험 목록
- 백엔드만 고칠 때는 devtools 가 알아서 재기동한다 — 손댈 것 없다.
- 테스트: `./gradlew test`(백엔드 331건) / `cd frontend && npx vitest run`(151건) / `npm run build`(타입체크+번들)
- 키는 **전부 `.env`**(큐넷·JWT·메일·소셜·매니저). `oauth.yml` 은 `${KAKAO_CLIENT_ID}` 처럼 참조만 하는 구조 파일.
  둘 다 gitignore — 없어도 앱은 뜬다(해당 기능만 꺼짐)
- 매니저 화면: http://localhost:8101/manager/login — 로컬 계정 **manager / pass1234**.
  계정은 `src/main/resources/data.sql` 이 넣는다(H2 일 때만 실행 → 운영 MySQL 에는 안 들어간다).
  `.env` 의 MANAGER_* 에 값이 있으면 기동마다 **그 아이디로 계정이 하나 더** 생긴다(data.sql 의 manager 와 별개). 지금 로컬 `.env` 엔 값이 있다 — 헷갈리면 두 줄을 비운다

## 6. 알아둘 함정 (안 보면 헤맴)
- **문서 위치**: 시험 데이터 관련은 전부 **`설계/시험데이터/`** 로 모았다(2026-08-10). 나머지 설계는 `설계/설계문서/`.
- **큐넷 API**: `openapi.q-net.or.kr`는 **HTTP만**(HTTPS 타임아웃). 인증키 **Encoding/Decoding** 구분(자동인코딩 클라이언트는 Decoding). 상세 `설계/시험데이터/큐넷_API/README.md` §0.
- **시드가 여섯이다**: ① `seed/qnet_master.json`(**613종, jmCd 포함** — 큐넷 API 응답, 계열은 이름 접미사로 판정) ② `seed/exam_master.json`(478종, 비큐넷) — 둘 다 일정 없음, 로더 `CertificateMasterInitializer`(qnet 먼저 읽는다) ③ `seed/non_qnet_exams.json`(52종, **일정 있음**, 로더 `SeedFileScheduleSource`) ④ `seed/certificate_lifecycle.json`(폐지·개칭 26건) ⑤ `seed/rolling_exams.json`(상시 34종 — 코드가 안 맞으면 이름으로 찾는다) ⑥ `seed/schedules_snapshot.json`(전 소스 일정 스냅샷, 기동 전용). `exam_master.json` 은 **운영에서도 적재**되고(실참조 데이터), 일정 있는 `non_qnet_exams.json` 만 `@Profile("!prod")` 다. `provenance`가 `scraped`=실데이터(한능검·ADsP), `approx`=추정치(50종).
- **일정 없는 시험도 정상 취급**: `Certificate`(마스터)와 `ExamSchedule`(일정)이 분리 적재된다. 일정이 없으면 `hasSchedule=false` → 화면에 `일정 미정`. 예전 구조(일정 있어야 시험 존재)로 되돌리지 말 것.
- **스크래퍼는 기본 on**(`SCRAPE_ENABLED` 기본 true — `false` 로 끈다). 기동 때는 안 돌고 05:00 배치·명시적 재수집에서만 돈다. 테스트 yml 엔 이 키가 없어 빈이 안 뜨므로 **테스트는 네트워크를 안 탄다**(파싱은 `src/test/resources/fixtures/` 픽스처). 사이트가 바뀌면 수집 로그에 WARN 이 뜬다.
- **SecurityConfig**: 화면 경로는 목록이 아니라 규칙이다 — **백엔드 접두어가 아닌 GET 은 전부 열려 있고**(`GET /**` permitAll 이 맨 뒤), 실제 파일이 없으면 `SpaWebConfig` 가 index.html 로 돌려준다. 라우트를 추가할 때 손댈 곳이 없다(2026-09-03 변경, `SpaRoutingSecurityIntegrationTest` 가 지킨다). GET 이외(POST 등)는 여전히 각자 규칙에 걸린다.
- **모든 시험이 같은 모델**: `Certificate`+`ExamSchedule`로 들어가서 검색·관심·D-day·알림이 자동 동작. 소스 추가 = `ScheduleSource` 구현 1개 추가.
- **포트**: 로컬 백엔드는 **8101 고정**(2026-08-06 사용자 지시). 8080 은 다른 프로젝트가 점유하는 일이 잦아 기본값에서 뺐다.
- **프런트 프록시 함정 2건(2026-08-06 수정됨)**: ① `vite.config.ts` 가 `process.env.VITE_API_TARGET` 을 읽었는데 Vite 는 `.env` 를 `process.env` 에 넣지 않는다 → 항상 기본 포트로 프록시됐다. `loadEnv` 로 교체. ② `tsc -b` 가 `vite.config.js` 를 소스 폴더에 내보냈고 **Vite 는 `.js` 를 `.ts` 보다 먼저 읽어** 설정 수정이 반영되지 않았다. `outDir` 을 `node_modules/.tmp` 로 돌림.
- **셸에서 한글 쿼리 테스트 금지**: Git Bash 가 한글을 CP949 로 보내 `?query=토익` 이 400/0건이 된다. 앱 버그가 아니다 — `fetch` 스크립트(UTF-8 파일)로 확인할 것.
