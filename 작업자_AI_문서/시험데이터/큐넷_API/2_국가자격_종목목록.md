## 요청 / 응답

**호출 예** (파라미터는 `ServiceKey` 하나):
```
http://openapi.q-net.or.kr/api/service/rest/InquiryListNationalQualifcationSVC/getList?ServiceKey={SERVICE_KEY}
```

**응답 필드 (item 1건 = 종목 1개):**

| 필드 | 설명 | 예 |
|---|---|---|
| `jmcd` | **종목코드** (조인 키) | `1320` |
| `jmfldnm` | 종목명 | `정보처리기사` |
| `qualgbcd` / `qualgbnm` | 자격구분 | `T` / `국가기술자격` |
| `seriescd` / `seriesnm` | 계열 | `01` / `기술사`, `기사`, `기능사` … (전문자격은 자격명 자체: `공인중개사` 등) |
| `obligfldcd` / `obligfldnm` | 대직무분야 | `21` / `정보통신` |
| `mdobligfldcd` / `mdobligfldnm` | 중직무분야 | `211` / `정보기술` |

> **주의**: `seriesnm`이 국가기술자격은 **등급**(기능사/기사/기술사)을 뜻하지만, 국가전문자격은 **자격명 자체**(공인중개사, 세무사…)가 들어온다. certificate 매핑 시 자격구분(qualgbcd)에 따라 의미가 다름을 반영.

## 실측 결과 (실제 호출)

- **총 613종** = 국가기술자격 **513** + 국가전문자격 **100**.
- 계열(seriesnm) 분포 상위:

| 계열 | 수 |
|---|:--:|
| 기사 | 242 |
| 기능사 | 163 |
| 기술사 | 79 |
| 기능장 | 29 |
| 국가유산수리기능자 | 24 |
| 관광통역안내사 | 12 |
| (그 외 전문자격 공인중개사·세무사·관세사·감정평가사·변리사·손해평가사·물류관리사 등 각 1~6) | … |

- 종목코드 예: 정보처리기사 `1320`, 정보처리산업기사 `2290`, 한식조리기능사 `7910`.
- 원본 응답: `samples/종목목록_전체_613종.xml`.

## 매핑 제안 (→ certificate 테이블, 설계 04)

| certificate 컬럼 | 소스 |
|---|---|
| `source_code` | `jmcd` |
| `name` | `jmfldnm` |
| `series` | `qualgbcd`+`seriesnm` 로 분류 (TECHNICIAN/ENGINEER/… 또는 전문자격) |
| `agency` | 고정값 "한국산업인력공단" |
| `slug` | `jmfldnm` 기반 생성 (한글 URL 또는 로마자) |

> 직무분야(obligfld/mdobligfld)는 pSEO 내부링크(같은 분야 종목 추천)·검색 필터로 활용 여지.

## 구현 체크포인트 (활용가이드 PDF 반영)

- 엔드포인트 `{base}/getList`, GET, 파라미터는 인증키 **하나뿐**(검색·페이징 없음) → 1회 호출로 전체 수신.
- `resultCode == "00"` 일 때만 정상. 아니면 `resultMsg` 확인.
- **코드 필드는 zero-padding 문자열**(`jmcd`=`0752`, `seriescd`=`01`, `obligfldcd`, `mdobligfldcd`) — 숫자로 파싱하면 앞자리 0이 날아간다. String으로 보존.
- 서비스명 오타 `Qualifcation` 그대로 사용.
- 키 인코딩 함정은 [README §0](README.md) 참고(자동 인코딩 클라이언트는 Decoding 키).
- ⚠️ 원문 PDF에 제공기관 신청페이지 계정/비번이 평문으로 적혀 있으나(문서 작성자 계정 추정) 재사용 금지 — 본인 공공데이터포털 계정으로 발급.
