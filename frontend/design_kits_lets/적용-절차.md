> 이 문서는 디자인 킷 저장소의 `core/적용-절차.md` 사본이다. 킷 폴더만 받아도 완결되도록 함께 넣었다.
> 고칠 일이 있으면 킷 저장소 쪽 원본을 고친다.

# 도입 지시서 — 다른 프로젝트에 디자인 킷 붙이기

> **받는 쪽 AI 에게 이 문서를 읽히면 된다.** 웹이든 앱이든, Spring 이든 Node 든 절차는 같다.
> 킷 폴더 하나를 통째로 복사하면 그 안에 이 문서와 `클래스-목록.md`, 필요한 CSS 가 전부 들어 있다.

---

## 0. 30초 요약

```
1. kits/design_kits_<고른킷>/ 폴더를 통째로 프로젝트에 복사한다   ← 이 폴더 하나면 끝. 다른 건 필요 없다
2. <link rel="stylesheet" href="design_kits_<id>/design-kit.css">   ← 한 줄
3. 마크업에 .k-* 클래스를 붙인다  ← 목록은 같은 폴더의 클래스-목록.md
4. 색·크기는 절대 하드코딩하지 않는다. 전부 var(--토큰)
```

킷 폴더는 **자급자족**하도록 만들어져 있다. 공용 컴포넌트 CSS·문서·Flutter 파일이
각 킷 폴더 안에 이미 복사돼 들어 있어서, 저장소의 다른 폴더를 같이 챙길 필요가 없다.

**디자인이 마음에 안 들면 4번까지 다 해 놓고 폴더만 다른 킷으로 갈아 끼우면 된다.**
클래스 계약(`.k-*`)과 번들 파일명(`design-kit.css`)이 모든 킷에서 같으므로 **마크업은 안 바뀐다.**
폴더 이름에 킷 id 가 들어 있으니 `<link>` 경로 한 줄만 새 폴더로 고치면 끝이다.

## 1. 킷 고르기

킷 저장소의 `kits/index.json` 에 각 킷의 `bestFor` / `avoid` / `modes` 가 들어 있다. 읽고 고른다.
(이미 킷 폴더만 받았다면 그 안의 `사용법.md` 에 같은 내용이 있다.)

| id | 한 줄 | 대표 용도 |
|---|---|---|
| `utility` | 도구는 조용해야 한다 | 관리자·사내 도구·CRUD |
| `dashboard` | 많이 보여주되 조용하게 | 관제·분석 (**다크 전용**) |
| `halo` | 화려함을 한 곳에 모은다 | B2C·랜딩·SaaS 소개 |
| `editorial` | 글이 주인공이다 | 콘텐츠·문서·브랜드 |
| `brutal` | 숨기지 않는다 | 이벤트·캠페인·포트폴리오 |
| `terminal` | 개발자에게 익숙한 화면 | 개발자 도구·로그·콘솔 |
| `cozy` | 따뜻하고 손이 가는 | 커머스·예약·라이프스타일 |
| `pop` | 누르고 싶게 만든다 | 교육·10~20대·리워드 |
| `lets` | 밝고 반듯한 서비스 화면 | 교육·커리어 플랫폼·회원제 콘텐츠 |
| `lucid` | 화려함을 덜어낸 자리 | B2C·SaaS 소개 (Halo 의 정돈된 대체제) |
| `slate` | 색을 거의 쓰지 않는다 | 개발자 서비스·콘솔·설정 |
| `calm` | 여백이 절반이다 | 오래 읽는 화면·상담·안내 |

눈으로 고르려면 `index.html` 을 브라우저로 열어 **전체 비교** 모드를 본다.
고른 뒤 폴더 안 `사용법.md` 로 그 킷의 원칙을 확인한다.

## 2. 복사할 것 — 킷 폴더 하나

```
디자인킷저장소/kits/design_kits_utility/     →     프로젝트/design_kits_utility/
```

**폴더 이름은 그대로 둔다.** `design_kits_` 로 시작하니까 나중에 프로젝트를 열었을 때
그게 디자인 킷이라는 걸 폴더명만 보고 알 수 있다 — 그러라고 붙인 이름이다.

끝이다. 골라 담을 것도, 빠뜨릴 것도 없다. 폴더 안에는 이미 이게 다 들어 있다.

| 파일 | 무엇 | 모든 킷 공통? |
|---|---|---|
| `design-kit.css` | 아래 CSS 를 전부 합친 **한 파일 번들** | — |
| `base.css` | 리셋·문서 기본값·포커스링 | ● 같음 |
| `components.css` | `.k-*` 컴포넌트 전부 — **이게 알맹이** | ● 같음 |
| `mobile.css` | 앱형 셸 (앱바·탭바·리스트·시트·FAB) | ● 같음 |
| `tokens.css` | **이 킷의 색·치수** | ○ 킷마다 다름 |
| `extras.css` | 킷 고유 표현 (있는 킷만) | ○ |
| `tokens.json` | 단일 소스 (참고용) | ○ |
| `kit_theme.dart` / `tokens.dart` | Flutter | ●/○ |
| `tailwind.preset.js` | Tailwind 프리셋 | ○ |
| `사용법.md` | **여기부터 읽는다** — 이 킷의 성격 + 적용법 | ○ |
| `클래스-목록.md` / `적용-절차.md` | 클래스 사전 / 이 문서 | ● 같음 |

실제로 킷마다 다른 건 `tokens.css` 뿐이다. 나머지는 모든 킷에서 바이트 단위로 같은 파일이다.
그래서 **킷 교체 = 폴더 교체** 로 끝난다.

안 쓰는 파일은 지워도 된다 (예: Flutter 안 쓰면 `*.dart`). **`base.css`·`components.css`·
`tokens.css` 세 개와 `클래스-목록.md` 는 지우지 말 것** — 각각 골격·컴포넌트·색, 그리고 AI 가 읽을 사전이다.

**여러 킷을 동시에 복사하지 않는다.** 하나만 쓴다. 나중에 바꿀 땐 그때 폴더를 갈아 끼운다.

## 3. 스택별 붙이는 법

### 3-1. 순수 HTML / 정적 사이트

```html
<!doctype html>
<html lang="ko" data-theme="light">
<head>
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <!-- 한 줄로 끝내려면 이것만: -->
  <link rel="stylesheet" href="/design_kits_<id>/design-kit.css">

  <!-- 나눠 쓰려면 (나중에 킷 교체 계획이 있으면 이쪽) -->
  <!--
  <link rel="stylesheet" href="/design_kits_<id>/base.css">
  <link rel="stylesheet" href="/design_kits_<id>/components.css">
  <link rel="stylesheet" href="/design_kits_<id>/mobile.css">
  <link rel="stylesheet" href="/design_kits_<id>/tokens.css">
  -->
</head>
<body>
  <div class="k-shell">…</div>
</body>
</html>
```

### 3-2. Spring Boot + Thymeleaf

1. 파일을 `src/main/resources/static/design_kits_<id>/` 아래에 둔다.
2. 공통 레이아웃(`templates/layout.html`)의 `<head>` 에 링크를 넣는다.

```html
<head th:fragment="head">
  <link rel="stylesheet" th:href="@{/design_kits_<id>/base.css}">
  <link rel="stylesheet" th:href="@{/design_kits_<id>/components.css}">
  <link rel="stylesheet" th:href="@{/design_kits_<id>/tokens.css}">
  <script th:inline="javascript">
    // 첫 페인트 전에 테마를 정한다 — 안 그러면 흰 화면이 번쩍인다
    (function(){var t=localStorage.getItem('theme');
      if(t) document.documentElement.dataset.theme=t;})();
  </script>
</head>
```

3. 캐시 무효화가 필요하면 파일명 대신 `?v=` 쿼리나 Spring 의 리소스 체이닝을 쓴다.

### 3-3. Spring Boot + React/Vue (CSR, 정적 서빙)

프런트 진입점에서 import 한다 — 번들러가 알아서 처리한다.

```js
// main.jsx / main.ts
import './design_kits_<id>/base.css';
import './design_kits_<id>/components.css';
import './design_kits_<id>/mobile.css';        // 앱형 화면을 쓸 때만
import './design_kits_<id>/tokens.css';
```

**React·Vue 라면 클래스를 그대로 쓰지 말고 얇게 감싼다.**
감싸되 **스타일은 만들지 않는다** — 클래스 이름만 조립한다. 그래야 킷 교체가 계속 공짜다.

```jsx
// components/ui/Button.jsx
export function Button({ variant = 'primary', size, block, className = '', ...props }) {
  const cls = [
    'k-btn', `k-btn--${variant}`,
    size && `k-btn--${size}`, block && 'k-btn--block', className,
  ].filter(Boolean).join(' ');
  return <button className={cls} {...props} />;
}

// components/ui/Card.jsx
export const Card = ({ hover, flush, className = '', ...p }) => (
  <div className={['k-card', hover && 'k-card--hover', flush && 'k-card--flush', className]
    .filter(Boolean).join(' ')} {...p} />
);
```

컴포넌트 안에 `style={{ color: '#6d5efc' }}` 같은 걸 쓰기 시작하면 그 순간부터 킷 교체가 안 된다.

### 3-4. Node — Next.js

```js
// app/layout.jsx
import '@/design_kits_<id>/base.css';
import '@/design_kits_<id>/components.css';
import '@/design_kits_<id>/tokens.css';

export default function RootLayout({ children }) {
  return (
    <html lang="ko" data-theme="light">
      <body>{children}</body>
    </html>
  );
}
```

SSR 이므로 `data-theme` 은 서버에서 정하거나, `<head>` 인라인 스크립트로 첫 페인트 전에 세팅한다.

### 3-5. Node — Express + EJS/Handlebars

`app.use(express.static('public'))` 아래에 파일을 두고 템플릿 `<head>` 에 `<link>` 3줄.
방식은 3-1 과 같다.

### 3-6. Tailwind 를 이미 쓰는 프로젝트

```js
// tailwind.config.js
module.exports = {
  presets: [require('./design_kits_<id>/tailwind.preset.js')],
  content: ['./src/**/*.{js,jsx,ts,tsx,html}'],
};
```

프리셋의 값은 전부 CSS 변수를 가리키므로 **`tokens.css` 를 함께 로드해야 한다.**
그러면 `bg-surface text-muted rounded-lg` 같은 유틸리티와 `.k-*` 컴포넌트를 섞어 쓸 수 있다.

### 3-7. Flutter

```dart
import 'design_kits_<id>/kit_theme.dart';
import 'design_kits_<id>/tokens.dart';

MaterialApp(
  theme: UtilityKit.light,
  darkTheme: UtilityKit.dark,
  themeMode: ThemeMode.system,
  home: const HomePage(),
);
```

위젯 안에서:

```dart
final t = KitTokens.of(context);
Container(
  decoration: BoxDecoration(
    color: t.surface,
    borderRadius: t.brLg,
    border: Border.fromBorderSide(t.side),
  ),
);
```

직접 위젯을 그릴 때도 같다:

```dart
class RoomTile extends StatelessWidget {
  final String name, sub;
  const RoomTile({super.key, required this.name, required this.sub});

  @override
  Widget build(BuildContext context) {
    final t = KitTokens.of(context);          // ← 색은 항상 여기서
    return Container(
      padding: const EdgeInsets.all(16),
      decoration: BoxDecoration(
        color: t.surface, borderRadius: t.brLg, border: Border.fromBorderSide(t.side),
      ),
      child: Row(children: [
        Expanded(child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text(name, style: TextStyle(fontWeight: FontWeight.w700, color: t.text)),
            Text(sub, style: TextStyle(fontSize: 13, color: t.muted)),
          ],
        )),
        const KitBadge('예약가능', status: KitStatus.ok),
      ]),
    );
  }
}
```

`Colors.grey` 나 `Color(0xFF...)` 를 쓰면 그 순간 다크 모드가 깨진다. 반드시 `KitTokens.of(context)`.

`kit_theme.dart` 아래쪽의 `KitBadge` · `KitCard` · `KitStat` · `KitAlert` 는
**전체 위젯 라이브러리가 아니라 "토큰을 이렇게 쓴다"는 본보기**다. 나머지는 같은 방식으로 만든다.

### 3-8. React Native / 그 외

폴더 안 `tokens.json` 이 **플랫폼 중립 단일 소스**다. 여기서 원하는 형태로 뽑아 쓴다.
변환기를 새로 쓸 거면 `tools/build.mjs` 의 출력 함수를 하나 더 추가하는 게 맞다
(손으로 값을 옮겨 적으면 반드시 동기화가 깨진다).

## 4. 기존 화면을 옮길 때 (마이그레이션 순서)

무작정 전부 바꾸지 말고 이 순서로 한다.

1. **레이아웃 먼저** — `.k-shell` / `.k-topnav` / `.k-main` / `.k-footer` 로 감싼다.
2. **버튼·입력** — 가장 많이 쓰이고 효과가 크다. `.k-btn` `.k-input` `.k-field`.
3. **카드·표·목록** — `.k-card` `.k-tablewrap`+`.k-table` `.k-rows`.
4. **상태 표시** — 배지·알림·빈 상태.
5. **남은 커스텀 CSS 청소** — 이 단계에서 색 하드코딩을 전부 걷어낸다.

한 화면씩 끝내고 다음으로 간다. 절반만 적용된 화면을 여러 개 만들지 않는다.

기존 CSS 와 충돌하면 원인은 대개 **기존 전역 스타일(`button {}`, `input {}` 같은 요소 선택자)** 이다.
`.k-*` 를 이기고 있으면 기존 규칙을 좁히는 쪽이 맞다 — `!important` 를 쌓지 않는다.

## 5. 프로젝트 색으로 바꾸고 싶을 때 (브랜드 오버라이드)

`tokens.css` 를 **고치지 않는다** (다음 빌드에 덮어쓰인다). 뒤에 한 겹 얹는다.

```css
/* brand.css — tokens.css 다음에 로드 */
:root {
  --point: #0f7b6c;
  --point-hover: #0b5f53;
  --point-soft: #e3f4f1;
  --point-text: #0b5f53;
  --on-point: #ffffff;
}
:root[data-theme="dark"] {
  --point: #4fd1bd;
  --point-soft: rgba(79, 209, 189, .16);
  --point-text: #6fdcc9;
  --on-point: #06201c;
}
```

지켜야 할 것:

- **`--point` 계열은 5개를 한 세트로 바꾼다.** 하나만 바꾸면 대비가 깨진다.
- `--on-point` 는 `--point` 위에 올라가는 글자색이다. 밝은 강조색에는 **어두운** 글자를 준다.
- 라이트·다크 **두 벌 모두** 준다. 한쪽만 바꾸면 반대 모드에서 브랜드가 사라진다.
- 대비는 본문 4.5:1, 큰 글자·UI 요소 3:1 이상을 지킨다.

킷을 영구적으로 고칠 거면 오버라이드가 아니라 **이 저장소의 `tokens.json` 을 고치고 재빌드**한다.

## 6. 완료 체크리스트

받는 쪽 AI 는 작업을 끝내기 전에 이걸 스스로 검토한다.

- [ ] CSS 로드 순서가 `base → components → (mobile) → tokens → (extras)` 인가
- [ ] 새로 쓴 CSS 에 `#`, `rgb(`, 하드코딩 `px` 색·치수가 없는가
- [ ] 다크 모드로 바꿔 봤는가 (`document.documentElement.dataset.theme='dark'`)
      — 입력창·달력 아이콘·표 헤더가 특히 잘 깨진다
- [ ] 모바일 폭(390px)에서 가로 스크롤이 생기지 않는가 (표는 `.k-tablewrap` 안에 있는가)
- [ ] 키보드 Tab 으로 모든 버튼·링크에 포커스 링이 보이는가
- [ ] 활성 상태를 `aria-current` / `aria-selected` / `aria-pressed` 로 표시했는가
- [ ] 주 버튼이 한 화면에 하나인가
- [ ] 킷이 지원하지 않는 모드를 강제하지 않았는가 (킷 폴더 `사용법.md` 의 «모드»)
- [ ] 공용 파일(`base.css` `components.css` `mobile.css`)을 수정하지 않았는가
      — 이 셋은 모든 킷이 공유하는 사본이다. 고쳐야 할 일이면 킷 저장소 쪽 원본에 반영한다

## 7. 트러블슈팅

| 증상 | 원인 | 조치 |
|---|---|---|
| 스타일이 하나도 안 먹는다 | CSS 경로가 틀렸다 | 개발자도구 Network 에서 404 확인 |
| 색은 바뀌는데 모양이 안 바뀐다 | `tokens.css` 만 넣고 `components.css` 를 빠뜨렸다 | 킷 폴더를 통째로 복사했는지 확인. 번들(`design-kit.css`)을 쓰면 애초에 안 생긴다 |
| 다크에서 입력창만 하얗다 | `input` 에 `.k-input` 을 안 붙였다 | 브라우저 기본 스타일이라 반드시 클래스가 필요하다 |
| 다크에서 달력 아이콘이 안 보인다 | 알려진 크롬 이슈 | `base.css` 에 처리돼 있다. `data-theme="dark"` 가 `<html>` 에 있는지 확인 |
| 모바일에서 가로 스크롤이 생긴다 | 표를 `.k-tablewrap` 없이 넣었다 | 감싼다 |
| 로드 시 흰 화면이 번쩍인다 | 테마를 첫 페인트 후에 세팅했다 | `<head>` 인라인 스크립트로 올린다 |
| 그라디언트·특수 효과가 안 나온다 | `extras.css` 누락 또는 순서 오류 | 번들을 쓰면 자동 해결. 나눠 쓴다면 `tokens.css` **다음** 에 로드 |
| 기존 CSS 가 킷을 이긴다 | 전역 요소 선택자(`button {}`, `input {}`)가 남아 있다 | 그 규칙을 좁힌다. `!important` 를 쌓지 않는다 |
| 다크 전용 킷인데 글자가 안 보인다 | 지원하지 않는 모드를 강제했다 | 킷 `사용법.md` 의 «모드» 확인 |

**테마 토글**이 필요하면:

```html
<button class="k-btn k-btn--ghost k-btn--sm" onclick="toggleTheme()">🌙</button>
<script>
function toggleTheme() {
  var el = document.documentElement;
  var next = el.dataset.theme === 'dark' ? 'light' : 'dark';
  el.dataset.theme = next;
  localStorage.setItem('theme', next);
}
</script>
```

## 8. 받는 쪽 AI 에게 그대로 줄 지시문

> 이 프로젝트에 디자인 킷을 적용해줘.
>
> 1. `design_kits_<id>/사용법.md` → `design_kits_<id>/클래스-목록.md` → `design_kits_<id>/적용-절차.md` 순으로 먼저 읽어라.
> 2. `design_kits_<id>/design-kit.css` 한 줄을 진입점에서 로드해라.
>    (파일을 나눠 쓸 거면 base.css → components.css → mobile.css → tokens.css → extras.css 순서.)
> 3. 기존 화면을 적용-절차.md §4 순서(레이아웃 → 버튼·입력 → 카드·표 → 상태 표시 → CSS 청소)로 옮겨라.
