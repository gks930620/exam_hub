# Lets — 밝고 반듯한 서비스 화면

> ⚠ 자동 생성 문서다. 고치려면 킷 저장소의 `kits/design_kits_lets/tokens.json` 을 고치고 `node tools/build.mjs`.

흰 바탕에 인디고 강조 하나, 연보라 면으로 섹션을 끊고 오렌지는 아주 조금. 정보가 많아도 답답하지 않은 교육·커리어 플랫폼 스타일.

---

# ■ 이 폴더를 받은 사람에게

**이 폴더 하나로 끝난다.** 다른 파일을 더 받을 필요 없다. 폴더째 프로젝트에 복사하고 아래대로 한다.
**폴더 이름(`design_kits_lets`)은 그대로 두는 걸 권한다** — 나중에 이게 뭐였는지 폴더명만 보고 알 수 있다.
바꾸려면 아래 경로들을 함께 바꿔야 한다.

## 1. 로드 — 둘 중 하나만 고른다

**A. 한 파일 (가장 빠름)**

```html
<link rel="stylesheet" href="design_kits_lets/design-kit.css">
```

**B. 파일 따로 (나중에 다른 킷으로 갈아탈 계획이면 이쪽)**

```html
<link rel="stylesheet" href="design_kits_lets/base.css">
<link rel="stylesheet" href="design_kits_lets/components.css">
<link rel="stylesheet" href="design_kits_lets/mobile.css">
<link rel="stylesheet" href="design_kits_lets/tokens.css">
<link rel="stylesheet" href="design_kits_lets/extras.css">
```

번들러를 쓴다면 진입점에서:

```js
import './design_kits_lets/base.css';
import './design_kits_lets/components.css';
import './design_kits_lets/mobile.css';
import './design_kits_lets/tokens.css';
import './design_kits_lets/extras.css';
```

**순서가 중요하다.** 위 순서 그대로 둘 것. `mobile.css` 는 앱형 화면(하단 탭바·앱바)을 안 쓰면 빼도 된다.

## 2. 테마

지원: **light + dark** · 기본: **light**

```html
<html lang="ko" data-theme="light">
```

생략하면 OS 설정을 따른다. 지정할 거면 **첫 페인트 전에** 세팅해야 화면이 번쩍이지 않는다:

```html
<head>
  <script>(function(){var t=localStorage.getItem('theme');
    if(t) document.documentElement.dataset.theme=t;})();</script>
  <!-- 그다음에 CSS -->
</head>
```

## 3. 화면 만들기

쓸 수 있는 클래스는 전부 [`클래스-목록.md`](클래스-목록.md) 에 있다. **새로 만들기 전에 거기서 먼저 찾는다.**

```html
<div class="k-shell">
  <header class="k-topnav">
    <a class="k-topnav__logo" href="/">서비스명</a>
    <nav><a href="/a" aria-current="page">첫 화면</a><a href="/b">두 번째</a></nav>
    <span class="k-spacer"></span>
    <button class="k-btn k-btn--primary">시작하기</button>
  </header>
  <main class="k-main">
    <h1 class="k-page-title">제목</h1>
    <div class="k-card">…</div>
  </main>
</div>
```

**색·크기를 하드코딩하지 않는다.** 전부 `var(--토큰)` 이다.
어기는 순간 다크 모드와 킷 교체가 동시에 깨진다.

## 4. Flutter

```dart
import 'design_kit/kit_theme.dart';
import 'design_kit/tokens.dart';

MaterialApp(
  theme: LetsKit.light,
  darkTheme: LetsKit.dark,
  themeMode: ThemeMode.system,
);
```

위젯에서 색은 항상 `KitTokens.of(context)` 로 꺼낸다 (`Colors.grey` 를 쓰면 다크가 깨진다).
`kit_theme.dart` 와 `tokens.dart` 는 **같은 폴더에 있어야** import 가 맞는다.

## 5. Tailwind (쓰는 경우만)

```js
// tailwind.config.js
module.exports = { presets: [require('./design_kits_lets/tailwind.preset.js')] };
```

프리셋 값은 전부 CSS 변수를 가리키므로 `tokens.css`(또는 번들)를 **함께 로드해야 한다**.

# ■ 이 킷의 성격

## 언제 이 킷을 쓰나

| 잘 맞는 곳 | 피할 곳 |
|---|---|
| 교육·강의 플랫폼<br>취업·커리어 서비스<br>정보량 많은 B2C 서비스<br>회원제 콘텐츠 사이트 | 고밀도 관리자 표<br>감성 브랜드 랜딩<br>처음부터 어두운 화면 |

## 지키면 이 킷이 되는 것 (원칙)

1. 흰 바탕 + 1px 선으로 구조를 만든다. 그림자는 hover 에만 잠깐.
2. 강조색은 인디고 하나. 오렌지(--point-2)는 '새로 생긴 것' 표시에만 아주 조금 쓴다.
3. 흰 화면이 길어지면 연보라 면(--hero-bg)으로 섹션을 끊는다.
4. 제목은 크고 굵게(800), 본문은 15px. 그 크기 차이로 읽는 순서를 만든다.

새 화면을 만들다 이 원칙과 어긋나면 킷을 벗어난 것이다. 예외를 두려면 왜인지 적어 둘 것.

| 강조 | `--point` | `#4b56e8` |

# ■ 이 폴더에 든 파일

| 파일 | 무엇 | 원본 |
|---|---|---|
| `design-kit.css` | 아래 CSS 를 전부 합친 한 파일 번들 | 생성물 |
| `base.css` | 리셋·문서 기본값·포커스링 | 저장소 `core/` 사본 |
| `components.css` | `.k-*` 컴포넌트 전부 — **이게 알맹이** | 저장소 `core/` 사본 |
| `mobile.css` | 앱형 셸 (앱바·탭바·리스트·시트·FAB) | 저장소 `core/` 사본 |
| `tokens.css` | **이 킷의 색·치수** — 다른 킷과 다른 유일한 CSS | 생성물 |
| `extras.css` | 이 킷 고유 표현. **빼면 인상이 절반쯤 죽는다** | 손으로 작성 |
| `tokens.json` | 단일 소스 (참고용) | 손으로 작성 |
| `kit_theme.dart` | Flutter 공통 — `KitTokens` + `buildKitTheme` | 저장소 `core/` 사본 |
| `tokens.dart` | 이 킷의 Flutter 값 | 생성물 |
| `tailwind.preset.js` | Tailwind 프리셋 | 생성물 |
| `사용법.md` | **이 문서.** 여기부터 읽는다 | 생성물 |
| `클래스-목록.md` | `.k-*` 클래스 사전 | 저장소 `core/` 사본 |
| `적용-절차.md` | 스택별 적용 절차·트러블슈팅 | 저장소 `core/` 사본 |

`base.css` `components.css` `mobile.css` `kit_theme.dart` `클래스-목록.md` `적용-절차.md` 는
**어느 킷에서나 같은 파일**이다. 킷을 갈아 끼울 때 실제로 바뀌는 건 `tokens.css` 뿐이다.
