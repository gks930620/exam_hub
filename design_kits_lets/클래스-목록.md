> 이 문서는 디자인 킷 저장소의 `core/클래스-목록.md` 사본이다. 킷 폴더만 받아도 완결되도록 함께 넣었다.
> 고칠 일이 있으면 킷 저장소 쪽 원본을 고친다.

# 클래스 계약 (Class Contract)

> **이 문서가 킷의 API 다.** 여기 적힌 클래스 이름은 모든 킷에서 전부 동일하다.
> 그래서 디자인 교체가 `tokens.css` 한 줄 교체로 끝난다 — 마크업은 손대지 않는다.
>
> 화면을 만들 때는 **먼저 여기서 맞는 조각을 찾는다.** 대개 있다.
> 없어서 새로 만들 때는 아래 §새 컴포넌트 규칙을 지킨다.

접두사는 `.k-` 다. 기존 프로젝트의 클래스와 충돌하지 않게 고른 이름이다.

---

## 0. 로드 순서

```html
<link rel="stylesheet" href="design_kits_<id>/design-kit.css">   <!-- 한 파일 번들 -->
```

나눠 쓴다면 **이 순서로**:

```html
<link rel="stylesheet" href="design_kits_<id>/base.css">        <!-- 리셋 + 문서 기본값 -->
<link rel="stylesheet" href="design_kits_<id>/components.css">  <!-- .k-* 컴포넌트 -->
<link rel="stylesheet" href="design_kits_<id>/mobile.css">      <!-- 앱형 화면을 쓸 때만 -->
<link rel="stylesheet" href="design_kits_<id>/tokens.css">      <!-- 이 킷의 색·치수 -->
<link rel="stylesheet" href="design_kits_<id>/extras.css">      <!-- 킷에 있을 때만 -->
```

`base.css` `components.css` `mobile.css` 는 **어느 킷에서나 같은 파일**이다.
킷을 바꿔도 이 세 줄은 그대로고, 실제로 바뀌는 건 `tokens.css` 뿐이다.

## 1. 셸 (페이지 골격)

| 클래스 | 무엇 | 비고 |
|---|---|---|
| `.k-shell` | 페이지 전체 세로 골격 | `min-height:100vh` |
| `.k-shell--sidebar` | 좌측 사이드바 배치로 전환 | `.k-shell` 과 같이 씀 |
| `.k-topnav` | 상단 네비 (sticky) | 안에 `.k-topnav__logo`, `<nav>`, `.k-spacer` |
| `.k-topnav__logo` | 로고/서비스명 | 강조색으로 표시됨 |
| `.k-sidebar` | 좌측 사이드바 | `.k-sidebar__logo` / `__section` / `__nav` |
| `.k-main` | 본문 컨테이너 | `--content-max` 로 폭 제한, 가운데 정렬 |
| `.k-page-title` / `.k-page-desc` | 페이지 제목 / 설명 | |
| `.k-toolbar` | 제목 아래 필터·버튼 줄 | |
| `.k-footer` | 하단 | |
| `.k-hero` | 최상단 강조 블록 | 킷마다 인상이 가장 크게 갈리는 부분 |

**활성 표시는 `aria-current="page"`** 로 한다 (클래스가 아니다). 접근성과 스타일을 한 번에 얻는다.

```html
<div class="k-shell">
  <header class="k-topnav">
    <a class="k-topnav__logo" href="/">서비스명</a>
    <nav><a href="/a" aria-current="page">첫 화면</a><a href="/b">두 번째</a></nav>
    <span class="k-spacer"></span>
    <button class="k-btn k-btn--secondary k-btn--sm">로그인</button>
  </header>
  <main class="k-main">…</main>
  <footer class="k-footer">…</footer>
</div>
```

## 2. 버튼

| 클래스 | 무엇 |
|---|---|
| `.k-btn` | 기반 (반드시 함께) |
| `.k-btn--primary` | 주 동작. 화면당 하나가 원칙 |
| `.k-btn--secondary` | 보조 |
| `.k-btn--ghost` | 배경 없는 약한 동작 |
| `.k-btn--danger` | 파괴적 동작 |
| `.k-btn--sm` / `--lg` | 크기 |
| `.k-btn--block` | 가로 100% |
| `.k-btn--icon` | 정사각 아이콘 버튼 |

비활성은 `disabled` 속성(또는 `aria-disabled="true"`). 클래스가 아니다.
`<a>` 에 붙여도 같은 모양이 나온다.

## 3. 입력

| 클래스 | 무엇 |
|---|---|
| `.k-field` | 라벨+입력+도움말 한 묶음 (아래 여백 담당) |
| `.k-label` | 라벨 |
| `.k-input` / `.k-select` / `.k-textarea` | 입력 요소 |
| `.k-help` / `.k-help--err` | 도움말 / 오류 메시지 |
| `.k-checkbox` / `.k-radio` | 체크박스·라디오 |
| `.k-check-row` | 체크박스 + 텍스트 가로 배치 (`<label>` 로 감쌀 것) |
| `.k-switch` | 토글 스위치 (`<input type="checkbox" class="k-switch">`) |
| `.k-inputgroup` | 입력 + 버튼 가로 조합 |

오류 상태는 `aria-invalid="true"`.

```html
<div class="k-field">
  <label class="k-label" for="email">이메일</label>
  <input class="k-input" id="email" type="email" aria-invalid="true">
  <p class="k-help k-help--err">형식이 올바르지 않습니다.</p>
</div>
```

## 9. 모바일 (앱형) — `mobile.css` 필요

| 클래스 | 무엇 | Flutter 대응 |
|---|---|---|
| `.k-app` | 앱 화면 골격 (`.k-shell` 대신) | `Scaffold` |
| `.k-appbar` | 상단 앱바 | `AppBar` |
| `.k-appbar__back` / `__title` / `__action` | 뒤로 / 제목 / 우측 아이콘 | |
| `.k-app-hero` | 큰 제목 블록 | |
| `.k-app-main` | 본문 (탭바 높이만큼 아래 여백 자동) | `body` |
| `.k-searchbar` | 검색 입력 | `SearchBar` |
| `.k-chiprow` | 가로 스크롤 칩 줄 | `SingleChildScrollView(horizontal)` |
| `.k-list` / `.k-list--plain` | 리스트 컨테이너 | `ListView` |
| `.k-item` | 리스트 행 | `ListTile` |
| `.k-item__icon` / `__main` / `__title` / `__sub` / `__meta` / `__chevron` | 행 내부 | |

## 10. 테마 전환

```html
<html data-theme="dark">   <!-- light | dark, 생략하면 OS 설정 추종 -->
```

```js
document.documentElement.dataset.theme = 'dark';
```

SSR(Next.js·Thymeleaf 등)에서는 **첫 페인트 전에** `data-theme` 을 세팅해야 깜빡임이 없다.
`<head>` 안 인라인 스크립트가 가장 확실하다.

한 가지 모드만 지원하는 킷이 있다 (같은 폴더 `사용법.md` 의 «모드» 확인).
지원하지 않는 모드를 강제하지 말 것 — 대비가 무너진다. 다른 킷으로 바꾸는 게 맞다.

## 11. 새 컴포넌트를 만들 때 (반드시 지킬 것)

1. **먼저 이 문서에서 찾는다.** 조합으로 되는 경우가 대부분이다.
2. 없으면 만들되 **색·크기는 `var(--토큰)` 만 쓴다.**
   `#`, `rgb(`, 하드코딩된 `px` 가 새로 등장하면 잘못 가고 있는 것이다
   (예외: `0`, 구조용 `100%`/`auto`, 1px 헤어라인).
3. 새 값이 정말 필요하면 컴포넌트에 적지 말고 **`:root` 오버라이드로 토큰을 늘린다**
   (`적용-절차.md` §5 브랜드 오버라이드 참고). **라이트·다크 두 벌 모두** 값을 준다.
   킷 자체에 영구히 넣을 값이면 킷 저장소의 `tokens.json` 을 고치고 다시 받는다.
4. 이 킷에만 필요한 표현이면 `extras.css` 에 넣는다.
   `components.css` 는 **모든 킷이 공유**하므로 특정 킷 전용 규칙을 넣지 않는다.
5. 웹에 추가했으면 **Flutter 쪽(`kit_theme.dart`)에도 같은 이름으로** 추가한다.

## 12. 자주 하는 실수 (코드 리뷰 체크리스트)

- [ ] 색을 하드코딩했다 → 다크에서 깨진다
- [ ] `components.css` 에 특정 킷 전용 규칙을 넣었다 → 다른 킷이 오염된다
- [ ] 활성 상태를 `aria-current` / `aria-selected` / `aria-pressed` 대신 클래스로 처리했다
- [ ] 표를 `.k-tablewrap` 없이 넣었다 → 모바일에서 가로로 터진다
- [ ] 의미색을 버튼 배경으로 썼다
- [ ] 주 버튼(`--primary`)이 한 화면에 여러 개다
- [ ] `input`/`select`/`textarea` 에 `.k-input` 등을 안 붙였다 → 다크에서 흰 배경 그대로 남는다
- [ ] 킷이 지원하지 않는 모드를 강제했다
- [ ] `tokens.css` 를 직접 고쳤다 → 킷을 다시 받으면 사라진다. 별도 파일에서 `:root` 로 덮어쓸 것
