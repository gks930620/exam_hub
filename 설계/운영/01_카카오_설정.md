# 카카오 설정 가이드 — 로그인 + 알림톡

> 작성 2026-08-07. 이 프로젝트가 카카오에 의존하는 건 **두 가지**입니다.
> **① 카카오 로그인** (계정) · **② 알림톡** (알림). 그런데 **하는 곳이 다릅니다.**
> 코드는 둘 다 구현 완료 — 아래 값들만 채우면 됩니다.

## ⚠️ 먼저: 사이트를 헷갈리지 마세요

가장 많이 막히는 지점입니다. **카카오 개발자센터에서는 알림톡을 설정할 수 없습니다.**

| 사이트 | 여기서 하는 것 | 이 프로젝트에서 |
|---|---|---|
| **developers.kakao.com**<br>(카카오 개발자센터) | 앱 생성, **카카오 로그인**, REST API 키 | **①번만** — 로그인 |
| **center-pf.kakao.com**<br>(채널 관리자센터) | **카카오톡 채널** 개설·비즈니스 전환 | ②번 1단계 |
| **business.kakao.com**<br>(카카오 비즈니스) | 비즈니스 계정, 사업자 인증 | ②번 2단계 |
| **solapi.com** 등 대행사 | **발신프로필·템플릿·실제 발송 API** | ②번 3단계 |

> **왜 이렇게 나뉘나**: 카카오 로그인은 "개발자용 API"이고, 알림톡은 "광고·메시지 상품"이라
> 회사 안에서 다른 조직이 운영합니다. 그래서 계정도 콘솔도 따로입니다.
> 그리고 알림톡은 **카카오와 직접 계약이 불가능**해서 반드시 대행사를 거칩니다.

# ① 카카오 로그인 (developers.kakao.com)

**로그인이 안 되면 내 시험·알림 설정·글쓰기가 전부 막힙니다.** 사업자등록 없이 됩니다.

## 1-1. 체크리스트

- [ ] [developers.kakao.com](https://developers.kakao.com) 로그인 → **내 애플리케이션** → **애플리케이션 추가하기**
  - 앱 이름: `모든시험한번에보기`
  - 사업자명: 개인이면 본인 이름
- [ ] **앱 설정 → 앱 키** → **REST API 키** 복사 → `KAKAO_CLIENT_ID`
- [ ] **제품 설정 → 카카오 로그인** → **활성화 설정 ON**
- [ ] 같은 화면에서 **Redirect URI 등록** (아래 그대로 복사)
      ```
      http://localhost:8081/login/oauth2/code/kakao
      ```
- [ ] **제품 설정 → 카카오 로그인 → 동의항목**
  - `닉네임`(ID: `profile_nickname`) — **필수 동의**. 우리가 요청하는 건 이것 하나뿐입니다
  - `프로필 사진` 은 **안 켜도 됩니다** — 헤더 아바타에만 쓰고, 없으면 닉네임 첫 글자로 대체됩니다.
    켜고 싶으면 동의항목을 먼저 켠 뒤 `KAKAO_SCOPE=profile_nickname,profile_image` 로 늘리세요
  - ⚠️ **여기서 켠 항목만** `.env` 의 `KAKAO_SCOPE` 에 넣을 수 있습니다 — 아래 1-3 을 꼭 읽으세요
- [ ] **보안** → **Client Secret 생성** → 기록
  - 생성 후 **활성화 상태 ON** 으로 바꿔야 합니다 (만들기만 하면 적용 안 됨)
- [ ] 프로젝트 루트에서 `cp oauth.yml.example oauth.yml` (구조만 있는 파일 — 키는 안 적습니다)
- [ ] **`.env`** 에 `KAKAO_CLIENT_ID` / `KAKAO_CLIENT_SECRET` 넣기 ← 실제 키는 여기

> `카카오계정(이메일)`·`카카오톡 메시지 전송` 은 **지금 켜지 마세요.** 비즈 앱 전환이 필요해
> 켤 수 없고, 켜지 않은 채 요청하면 로그인이 통째로 막힙니다(1-3).

## 1-2. 키는 `.env`, 구조는 `oauth.yml`

**비밀값은 전부 `.env` 한 곳에** 모읍니다. `oauth.yml` 은 `${KAKAO_CLIENT_ID}` 처럼 참조만 하는
구조 파일입니다 — 키가 두 파일에 흩어져 있으면 어디를 고쳐야 하는지 헷갈리기 때문입니다.

`oauth.yml` 이 없으면 **로그인만 꺼지고** 시험 조회·커뮤니티 읽기는 그대로 돕니다.
둘 다 `.gitignore` 라 저장소에 올라가지 않습니다.

**배포하면 두 파일 다 없습니다.** 대신 환경변수로 같은 값을 넣습니다 —
카카오 provider(토큰·유저정보 URI)는 비밀이 아니라 `application.yml` 에 있으므로 넣을 필요가 없고,
등록 정보만 넣으면 됩니다. 정확한 목록은 [진행사항/02_내가_할일.md](../../진행사항/02_내가_할일.md) 4순위.

## 1-3. ⚠️ KOE205 — 가장 많이 막히는 곳

로그인 버튼을 눌렀는데 이런 화면이 뜬다면:

```
Invalid Request (KOE205)
An error in the test service settings prevents the service from being used.
The service admin's confirmation is required.
```

**동의항목 문제입니다.** 카카오 공식 문서의 정의가 그렇습니다:

> 앱에 설정하지 않은 카카오 로그인 동의항목을 포함해 인가 코드를 요청한 경우

즉 **키·리다이렉트가 아니라 `scope`** 입니다. 키를 다시 발급받지 마세요.

### ⚠️ 로그인 화면이 떴다고 설정이 맞는 게 아니다

`/oauth/authorize` 는 **로그인 전에는 아무것도 검사하지 않습니다.** 실제로 재 봤습니다:

| 일부러 틀린 것 | 결과 |
|---|---|
| 앱키를 0으로 도배 | 302 → 로그인 화면 (막지 않음) |
| 등록 안 한 포트(:9999) | 302 → 로그인 화면 (막지 않음) |
| 없는 scope 이름 | 302 → 로그인 화면 (막지 않음) |

**검사는 로그인을 마친 뒤 동의 화면에서 일어납니다.** 그래서 "로그인 창까지는 뜨던데"는
아무 증거가 못 됩니다 — 이 함정을 두 번 밟았습니다.

### 로그인 없이 확인되는 건 앱키뿐

토큰 엔드포인트는 앱키를 즉시 검증합니다. 가짜 인가코드를 넣어도 앱키가 맞으면
**KOE320**(코드 없음)까지 가고, 틀리면 **KOE101** 에서 끊깁니다:

```bash
curl -s -X POST https://kauth.kakao.com/oauth/token   -d grant_type=authorization_code -d client_id="$KAKAO_CLIENT_ID"   -d redirect_uri=http://localhost:8081/login/oauth2/code/kakao -d code=probe
# KOE320 → 앱키 정상 (리다이렉트는 이 단계에서 검사하지 않는다)
# KOE101 → 앱키 틀림
```

### 그래서 KOE205 는 이 순서로 본다

1. **개발자센터 → 카카오 로그인 → 동의항목** 을 열고, `.env` 의 `KAKAO_SCOPE` 에 적힌 ID가
   **그 화면에 있고 상태가 "사용 안 함"이 아닌지** 하나씩 대조합니다.
   신규 앱은 닉네임조차 **기본이 꺼짐**이라, 코드가 맞아도 막힙니다.
   지금 기본값은 `profile_nickname` 하나뿐이라, 이게 막히면 그 항목이 꺼져 있다는 뜻입니다.
2. **가장 빠른 우회 — `KAKAO_SCOPE=` 를 비웁니다.** 그러면 scope 를 아예 안 보내고
   카카오가 앱에 설정된 동의항목만 씁니다. **KOE205 가 원천적으로 못 납니다.**
   닉네임이 안 와도 가입은 됩니다(`MemberService.uniqueNickname` 이 "회원" 으로 채움).
3. 비우면 되고 넣으면 안 된다면, 하나씩 늘려 범인을 특정합니다
   (`profile_nickname` → 필요하면 `,profile_image`). 서버 재시작이 필요합니다.

**비즈 앱 전환(사업자 정보 등록) 전에는 켤 수 없는 항목** — 그래서 지금 `scope` 에서 빼 두었습니다:

| 항목 | 왜 못 켜나 | 대신 |
|---|---|---|
| `account_email` | 비즈 앱 전용 | **내 정보 화면에서 직접 입력** (`PUT /api/me/email`) |
| `talk_message` (나에게 보내기) | 비즈 앱 전용 | 이메일 알림 |
| `카카오계정(전화번호)` | 비즈 앱 전용 | 내 정보 화면에서 직접 입력 |

**여기서 이어지는 결과** — 카카오 로그인은 **이메일을 주지 않습니다.**
알림 채널이 이메일뿐이므로, 사용자가 내 정보에서 이메일을 넣지 않으면 알림이 하나도 안 갑니다.
그래서 이메일이 비면 화면이 "알림을 받을 수 없는 상태"라고 경고합니다.

계정 식별은 원래부터 이메일이 아니라 `(제공자, 제공자ID)` 라서, 이메일이 없어도 로그인·가입은 정상입니다.

**비즈 앱으로 전환한 뒤** 동의항목을 켜고 `KAKAO_SCOPE` 에 추가하면 됩니다:

```bash
# .env — 비즈 앱 전환 후 동의항목을 켜고 나서 추가
KAKAO_SCOPE=profile_nickname,profile_image,account_email,talk_message
```

## 1-4. 배포하면

Redirect URI 를 **하나 더 추가**하세요 (로컬 것은 지우지 말 것).
```
https://내도메인/login/oauth2/code/kakao
```

# ② 카카오 알림톡

**여기서부터는 개발자센터가 아닙니다.** 그리고 **사업자등록증이 첫 관문**입니다.

총 **3~5 영업일** (템플릿 심사 1~2일 포함).

## 🧪 사업자등록 전에 카톡 알림을 테스트하는 법

**결론부터: 알림톡은 사업자등록 없이 테스트조차 안 됩니다.**
발신프로필 등록에 사업자등록번호가 필수라, 나에게 한 통 보내는 것도 막힙니다.

**대신 "나에게 보내기"가 있습니다.** 카카오 공식 문서 기준
*"사용 권한이 없는 앱과 그 앱의 테스트 앱에서는 **앱의 멤버에게만** 메시지를 보낼 수 있습니다"* —
즉 **본인·팀원에게는 사업자 없이 진짜 카톡이 옵니다.**

| | 알림톡 | 나에게 보내기 |
|---|:-:|:-:|
| 사업자등록 | 필요 | **불필요** |
| 받는 사람 | 누구나 | **앱 멤버(본인·팀원)만** |
| 비용 | 건당 8원 | **무료** |
| 문구 심사 | 필요 | 불필요 |
| 쓰임 | **운영** | **개발·테스트** |

### 켜는 법 (5분)

1. `oauth.yml` 에 카카오 키를 넣습니다 (§1 참고). **scope 에 `talk_message` 가 있어야 합니다** — `.env` 의 `KAKAO_SCOPE` 에 **추가**해야 하고(예시 파일엔 없음), 개발자센터 동의항목을 먼저 켜야 합니다(안 켜면 KOE205 로 로그인 자체가 막힘)
2. 개발자센터 → **카카오 로그인 → 동의항목 → "카카오톡 메시지 전송"** 을 켭니다
3. 개발자센터 → **앱 설정 → 팀 관리** 에서 본인 계정이 멤버인지 확인 (앱 만든 사람은 자동)
4. `.env` 에 `KAKAO_MEMO_ENABLED=true`
5. 재기동 → **카카오로 로그인** → 알림이 뜰 때 본인 카톡으로 옵니다

로그에 이렇게 찍히면 준비된 겁니다:
```
[알림] 발송 채널 순서: [KAKAO_MEMO, EMAIL, LOG]
```

> 토큰은 로그인할 때 자동으로 보관됩니다(액세스 6시간 / 리프레시 약 2개월).
> 만료되면 알아서 갱신하고, 2개월 넘게 로그인을 안 하면 다시 로그인해야 합니다.

> ⚠️ 이건 **운영 채널이 아닙니다.** 일반 사용자에게 열려면 비즈앱 전환이 필요하고
> 그건 결국 사업자등록입니다. 사업자가 나오면 알림톡을 켜세요 —
> 체인이 알림톡을 먼저 쓰므로 설정만 바꾸면 자동으로 넘어갑니다.

## 2-0. 왜 알림톡인가

카카오톡으로 메시지를 보내는 방법은 2026년 기준 **두 가지뿐**입니다.

| 방식 | 성격 | 발송 대상 | 우리에게 |
|---|---|---|:-:|
| **알림톡** | 정보성 전용 (광고 금지) | **채널 친구 추가를 안 해도 발송 가능** | ✅ 정답 |
| 브랜드메시지 | 광고·마케팅 | 마케팅 수신동의자 | ❌ 우리는 광고를 안 보냄 |
| ~~친구톡~~ | ~~광고~~ | ~~채널 친구~~ | 2025-12-31 종료 |

우리 알림은 "사용자가 직접 등록한 시험의 일정 안내"라 **정보성 요건에 정확히 맞습니다.**
그리고 **채널 친구 추가가 필요 없어서** "알림 받으려면 채널 추가하세요" 허들이 없습니다.

## 2-1. 사업자등록증 (즉시~1일)

- [ ] 홈택스 → 사업자등록 신청 (개인사업자, 온라인)
- [ ] 업종은 "정보서비스업" 계열
- [ ] **사업자등록증 PDF 저장** ← 이후 단계마다 계속 씁니다

## 2-2. 카카오톡 채널 개설 — center-pf.kakao.com (30분)

- [ ] [center-pf.kakao.com](https://center-pf.kakao.com) → **채널 만들기**
  - 채널명: `모든시험한번에보기` (사용자에게 이 이름으로 보입니다)
- [ ] **비즈니스 채널로 전환** — 사업자등록증 업로드
- [ ] **홈 공개 ON** ← 안 켜면 심사에서 막힙니다
- [ ] **고객센터 정보 입력** (전화번호 또는 URL) ← 이것도 필수
- [ ] 채널 검색용 ID 기록

> 이 두 가지(홈 공개·고객센터)가 안 되어 있어 반려되는 경우가 가장 많습니다.

## 2-3. 대행사 가입 — solapi.com (30분)

카카오와 직접 계약은 불가능하고 **공식 딜러사**를 거쳐야 합니다.

- [ ] [SOLAPI](https://solapi.com) 가입 (코드가 이 회사 기준입니다)
- [ ] **API Key** 발급 → `ALIMTALK_API_KEY`
- [ ] **API Secret** 발급 → `ALIMTALK_API_SECRET` (다시 못 봅니다, 바로 저장)
- [ ] 잔액 충전 (선불제. 테스트는 1만원이면 충분)

> 다른 대행사(NHN Cloud·알리고)도 됩니다. `KakaoAlimtalkSender` 한 파일만 고치면 됩니다.

## 2-4. 발신프로필 · 발신번호 (1~2일)

- [ ] 대행사 콘솔 → 카카오 채널 연동 → 2-2 에서 만든 채널 연결
- [ ] **발신프로필 키(pfId)** 발급 → `ALIMTALK_PF_ID`
- [ ] **발신번호 등록** — 본인 명의 번호 + 통신서비스 이용증명원 → `ALIMTALK_FROM`
- [ ] 승인 대기 (보통 1영업일)

## 2-5. 템플릿 4개 심사 (1~2일)

- [ ] 대행사 콘솔 → 템플릿 등록

- [ ] 4개 모두 심사 신청 → 승인되면 **템플릿 코드 4개** 기록

# ③ 템플릿 문구 — 그대로 복사해 제출

알림톡은 **승인된 문구만** 보낼 수 있고 `#{변수}` 자리만 바뀝니다.

> **통과 요령**: "지금 신청하세요", "할인", "이벤트", "혜택" 같은 말은 절대 금지입니다.
> 광고로 분류되면 반려됩니다. 아래 문구는 그 부분을 이미 피해서 썼습니다.

### ① 접수 시작 — `EXAM_REG_OPEN`

```
[모든시험한번에보기] 원서접수 시작 안내

#{닉네임}님이 등록하신 시험의 원서접수가 시작되었습니다.

▶ 시험명: #{시험명}
▶ 접수 일정: #{일정}

#{안내}

본 안내는 관심 시험으로 등록하신 내역에 따라 발송되었습니다.
최종 일정은 시행처 공고를 확인해 주세요.
```

### ② 접수 마감 임박 — `EXAM_REG_CLOSING` ★가장 중요

```
[모든시험한번에보기] 원서접수 마감 안내

#{닉네임}님이 등록하신 시험의 접수 마감이 다가옵니다.

▶ 시험명: #{시험명}
▶ 마감 일시: #{일정}

#{안내}

본 안내는 관심 시험으로 등록하신 내역에 따라 발송되었습니다.
최종 일정은 시행처 공고를 확인해 주세요.
```

### 변수 4개 — 이름까지 정확히

코드가 이 이름으로 치환합니다(`KakaoAlimtalkSender.variables()`). 하나라도 다르면 발송이 거부됩니다.

| 변수 | 들어가는 값 |
|---|---|
| `#{닉네임}` | 회원 닉네임 |
| `#{시험명}` | 정보처리기사 등 |
| `#{일정}` | 2027-01-14 18:00 등 |
| `#{안내}` | 상황별 한 문장 |

**버튼**(선택): 웹링크 버튼 1개, 이름 `일정 확인하기`, 링크는 배포 도메인.

# ⑤ 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 개발자센터에 알림톡 메뉴가 없다 | **사이트가 다릅니다** | 맨 위 표 참고 — 채널 관리자센터 + 대행사 |
| 로그인 후 `redirect_uri_mismatch` | Redirect URI 불일치 | 등록한 주소와 접속 주소가 **완전히** 같아야 함 (http/https, 포트 포함) |
| Client Secret 넣었는데 인증 실패 | 생성만 하고 **활성화 OFF** | 보안 메뉴에서 활성화 ON |
| 이메일이 안 옴 | 사용자가 선택 동의 거부 | 정상. 화면이 그 사실을 안내함 |
| 채널 심사 거부 | 홈 공개 OFF / 고객센터 정보 없음 | 2-2 다시 확인 |
| 템플릿 반려 | 광고성 문구 | §3 문구 그대로 사용 |
| 발송 거부 | 변수명 불일치 | 승인 템플릿의 `#{}` 와 코드가 정확히 같아야 함 |
| 발신번호 등록 거부 | 명의 불일치 | 본인 명의 번호 + 통신서비스 이용증명원 |
| 일부 사용자만 안 감 | 카톡 미사용·차단 | 정상. 이메일로 폴백 (`notification_log` 확인) |
| **계정 영구 정지** | 신고 누적 | **사업자등록번호 기준으로 차단**됩니다. 광고성 발송 절대 금지 |

# ⑥ 우리 구현 요약

## 채널 우선순위

```
알림톡 ──성공──> 끝
  │
  └─실패/불가──> 이메일 ──성공──> 끝
                   │
                   └─실패──> 로그
```

번호를 안 넣은 사람, 카톡을 안 쓰는 사람, 차단한 사람이 반드시 있습니다.
"접수 마감을 놓치지 않게 한다"가 약속이라 채널 하나 죽었다고 아무것도 안 보내면 안 됩니다.
실제로 나간 채널은 `notification_log.channel` 에 남습니다.

## SMS 대체발송은 꺼 두었습니다

솔라피는 알림톡 실패 시 자동으로 SMS 를 보내는 게 기본입니다. 추가 과금이라
모르는 사이에 돈이 나가면 안 되므로 껐습니다(`disableSms: true`).
켜려면 `ALIMTALK_SMS_FALLBACK=true`.
