# 05. 디자인 시스템 (Lets)

> **이 문서는 무엇인가**
> 화면을 만들 때 지켜야 할 시각 규칙이다. Lets 디자인 킷의 원칙 + 이 프로젝트가 실제로 적용한 규칙(강조 예산, 3줄 병기,

> **클래스 계약의 원문은 `design_kits_lets/클래스-목록.md`** — 이것이 킷의 API다. 화면을 만들 땐 거기서 먼저 찾는다.
> 킷 성격은 `design_kits_lets/사용법.md`, 적용 절차는 `design_kits_lets/적용-절차.md`.

기준일: **2026-09-03 — Halo → Lets 킷 전면 교체**(§1~§14 개정, §15~§18은 제품 규칙이라 표현만 갱신)

## 1. 한 줄 원칙

> **밝고 반듯하게.** 흰 바탕과 1px 선으로 구조를 만들고, 강조는 인디고 하나로 끝낸다.

정보량이 많아도 답답하지 않은 화면이 목표다. 이 사이트는 문법·한자·어휘가 끝없이 나열되는 학습 도구라
**장식이 아니라 위계**가 읽혀야 한다. 아래 모든 규칙은 이 문장을 지키는 방법일 뿐이다.

## 2. 네 가지 원칙

| # | 원칙 | 내용 |
|---|---|---|
| ① | **흰 바탕 + 1px 선으로 구조를 만든다** | 카드·패널·표의 경계는 `--border` 1px이다. **그림자는 hover에만 잠깐**(`--sh-2`). 상시 그림자로 면을 띄우지 않는다 |
| ② | **강조색은 인디고 하나** | `--point` 단색. **그라디언트를 쓰지 않는다.** 오렌지 `--point-2`는 "새로 생긴 것 / 여기부터" 표시에만 **아주 조금**(§3) |
| ③ | **흰 화면이 길어지면 연보라 면으로 끊는다** | `--hero-bg`. 히어로·구획 나눔이 이 면의 자리다. **`backdrop-filter`(유리)는 어디에도 쓰지 않는다** — 킷이 쓰지 않는 표현이다 |
| ④ | **크기 차이로 읽는 순서를 만든다** | 제목은 크고 굵게(`--w-heavy` 800 + `--display-tracking`), 본문은 `--t-md`(15px). 색을 늘리는 대신 **급간**으로 위계를 만든다 |

보조 규칙:

- **모양은 라운드 사각이다.** 버튼·입력은 `--r`(10px), 카드는 `--r-lg`(16px), 작은 타일은 `--r-sm`(8px).
  **알약(`--r-pill`)은 배지·진도 막대·아바타처럼 "값을 담은 조각"에만** 쓴다. 버튼을 알약으로 만들지 않는다.
  *(Halo 시절의 "버튼·칩·배지는 전부 알약, 예외 없다"는 폐기됐다.)*
- **면이 겹치면 안쪽을 낮춘다.** 카드 안 박스는 `--surface-alt`, 페이지 배경은 `--bg`.
  선 위에 선을 겹치지 않는다 — 카드 안 표의 바깥 테두리는 지운다.
- **의미색(`--ok`/`--warn`/`--err`)은 상태 표시용이다.** 버튼 배경에 쓰지 않는다(파괴적 동작 `.k-btn--danger`만 예외).
- **큰 제목은 자간을 좁힌다** (`--display-tracking` = -.035em).
- **`#hex`를 쓰고 싶어지면 토큰이 하나 부족한 것이다.** 하드코딩 대신 `frontend/src/styles/project-tokens.css`에
  `:root` + `:root[data-theme="dark"]` **두 벌**로 토큰을 추가한다(킷 `클래스-목록.md` §11-3).
  **킷 파일(`base`·`components`·`tokens`·`extras`)은 한 줄도 고치지 않는다** — 다음 킷 교체 때 사라진다.
  이 프로젝트가 실제로 추가한 토큰은 **`--font-jp`(일본어 폰트 스택) 하나뿐**이다.
  *(Halo 시절의 `--dim`은 킷의 `--overlay`로 대체됐다.)*
- 허용된 예외는 둘뿐이고 **둘 다 코드 주석에 사유가 적혀 있어야 한다**:
  카카오 브랜드 색(브랜드 가이드 고정값, 테마 종속 아님)과 `.tts-btn`의 28px 고정폭(§15-3, 3줄 병기 줄 높이를 지키는 값).

## 3. 강조 예산 — 이 프로젝트의 적용 규칙

> Halo 시절엔 "그라디언트 예산"이었다. Lets에는 그라디언트가 없으므로 **세는 대상이 바뀌었다.**
> 예산이라는 장치 자체는 남는다 — 그것이 **정보 위계를 강제하는 방법**이기 때문이다.

### 3-1. 세는 것은 세 가지다

| 강조 수단 | 무엇 | 예산 |
|---|---|---|
| **A. 주 버튼** `.k-btn--primary` | 인디고 면 버튼 | **화면당 1개** |
| **B. 인디고 강조 면** `--point`/`--point-soft` 배경 | 활성 메뉴 밑줄·활성 탭·선택 칩·아바타 글리프·페이지네이션 현재·진도 막대 채움 | **화면당 6개 이하** |
| **C. 오렌지** `--point-2` | "새로 생긴 것 / 여기부터" 알약 배지 | **화면당 0~1개** |

**세지 않는 것**: `--border` 1px 선, hover 그림자, 의미색 상태 표시(정답·오류·완료), `--hero-bg` 연보라 면.
이것들은 초점이 아니라 구조·상태다.

### 3-2. 예산 규칙 (확정)

- **화면당 `.k-btn--primary`는 1개.** 어느 상태에서도 동시에 둘이 되지 않는다 — 상태가 전환되며 **라벨만 바뀐다**
  (퀴즈: 문제 풀기 → 다음 문제 → 다음 유닛). 같은 화면에 진행 버튼이 두 벌 생기면 그 화면은 잘못 설계된 것이다.
- **오렌지는 화면에 하나다.** 코스 목록의 "여기부터" 1장, 유닛 목록의 "여기부터" 1행. 둘이 같은 화면에 있으면 하나를 지운다.
  **오렌지를 반복 요소·상태색·버튼에 쓰지 않는다.**
- **반복 요소에 강조 면을 깔지 않는다.** 한자 타일 60개·문법 행 20개·어휘 표 행 50개·레벨 배지·태그·품사 라벨·적용 칩·결과 개수 — 전부 금지.
  **선택된 칩은 예외**다(선택은 상태이지 장식이 아니다) — `--point-soft`, `aria-pressed="true"`.
- **히어로 위 CTA는 `.k-btn--primary` 그대로.** 연보라 면(`--hero-bg`) 위 인디고 버튼은 대비가 충분하다.
  *(Halo의 "히어로 위엔 primary 금지 → 흰 알약" 규칙은 그라디언트 위 그라디언트를 피하려던 것이라 근거째 사라졌다.)*

GNB가 기본으로 소비하는 몫: 활성 메뉴 밑줄 **1개**(홈처럼 활성 메뉴가 없으면 0).
로고는 킷이 `--point` 글자색으로 칠하므로 **면이 아니라 글자다 — 세지 않는다.**

| 화면 | B(인디고 면) 내역 | 합계 |
|---|---|---:|
| 코스 목록 | 활성 메뉴 1 · 진도 막대 n(반복 아님, 카드당 1) | 1 + 진도 |
| 유닛 학습 | 활성 메뉴 1 · 현재 스텝 칩 1 · 아바타 1 | 3 |
| 자료실 목록 | 활성 메뉴 1 · 아바타 1 · 활성 탭 1 · 선택 칩 n · 현재 페이지 1 | 4 + 선택 칩 |
| 실력 진단 | (**GNB 활성 메뉴 없음** — 진단은 메뉴가 아니다) | 0 |
| 편집 모드 띠 · 편집 패널 · 저장 결과 | 0 (`--warn-soft` 띠 · `.k-btn--danger` · ghost만) | +0 |

**퀴즈·실력 진단·음성·편집 모드·영어 과정이 새로 들인 강조는 여전히 0개다**(§15·§16).
진도·보관함도 0이다 — 진도 막대 채움은 `--point` 단색이고 ★는 텍스트 글리프다.

### 3-3. 예산이 실제로 설계를 바꾼 선례

코스가 4개 AVAILABLE이 되자 코스 목록의 강조가 7개로 늘어 예산을 넘겼다.
→ **"첫 AVAILABLE 코스 1장만 강조"**로 바꿨고, 그 판정을 하드코딩하지 않고
**AVAILABLE 중 `courseNo` 최솟값**으로 계산하게 만들었다(`lib/courses.js`).
코스가 더 늘어나도 자동으로 유지된다.
**킷이 바뀌어도 이 결정은 살아 있다** — 강조 수단만 그라디언트 배지에서 오렌지 알약 배지(`.k-badge--pill`)로 바뀌었다.

> 예산은 장식 규칙이 아니라 **정보 위계를 강제하는 장치**다. 예산을 넘겼다는 건 "무엇이 제일 중요한지"를 정하지 않았다는 뜻이다.

## 4. 토큰 (단일 출처: `design_kits_lets/tokens.css`)

**값은 이 문서가 아니라 킷의 토큰 파일이 정한다.** 여기엔 어떤 토큰이 무슨 용도인지만 적는다.
전체 목록은 `design_kits_lets/tokens.css`를 직접 본다.

| 분류 | 토큰 | 용도 |
|---|---|---|
| 강조 | `--point` `--point-hover` `--point-soft` `--point-text` `--on-point` | 링크·아이콘·포커스 / hover / 연한 강조 면 / soft 면 위 글자 / `--point` 면 위 글자 |
| 오렌지 | `--point-2` | **"새로 생긴 것 / 여기부터" 알약 배지 전용**(§3-1 C) |
| 면 | `--bg` `--bg-sunken` `--surface` `--surface-alt` `--surface-hover` | 페이지 / 가라앉은 면 / 카드·패널 / **카드 안 박스·입력·표 헤더** / hover |
| 선 | `--border` `--border-strong` | 카드·표 구분선 / 입력 테두리 |
| 텍스트 | `--text` `--muted` `--muted2` | 본문 / 보조 / 라벨·캡션 |
| 의미색 | `--ok` `--ok-soft` `--ok-text` · `--warn` `--warn-soft` `--warn-text` · `--err` `--err-soft` `--err-text` | 면/글자 쌍이 이미 있다 — **`color-mix()`로 계산하지 않는다** |
| 섹션 면 | `--hero-bg` `--hero-fg` | **연보라 면**(원칙 ③). 히어로·구획 나눔 |
| 반경 | `--r-sm`(8) `--r`(10) `--r-lg`(16) `--r-pill`(999) | 작은 타일 / 버튼·입력 / 카드 / 배지·막대·아바타 |
| 간격 | `--sp-1`…`--sp-10` (4·8·12·16·20·24·32·40) | 여백은 전부 이 계단에서 고른다 |
| 타이포 | `--t-xs`…`--t-3xl` · `--w-normal`…`--w-heavy` · `--lh` `--lh-tight` `--lh-relaxed` · `--font` `--font-mono` | 본문은 `--t-md`(15px) / `--lh`(1.65) |
| 그림자 | `--sh-1` `--sh-2` `--sh-3` `--sh-point` | 거의 안 쓴다 / **hover 전용** / 모달 / 포커스 링 |
| 그 밖 | `--overlay` `--focus` `--nav-h` `--content-max`(1200) `--touch`(46) `--dur` `--ease` | `--overlay`는 확인 대화상자 딤(§12-1) |
| **프로젝트 확장** | `--font-jp` | **일본어 전용 폰트 스택.** 킷에 대응이 없는 유일한 값 → `frontend/src/styles/project-tokens.css` |

킷 `base.css`의 전역 규칙: 리셋, `box-sizing`, body 폰트 `--font`/`--t-md`/`--lh`, 포커스 링.
**웹폰트 다운로드 없음(시스템 폰트만)** 정책은 유지한다 — `--font`의 Pretendard는 있으면 쓰고 없으면 폴백된다.
**배경 메시(radial-gradient)는 사라졌다.** Lets의 바탕은 흰색이고, 화면을 끊는 건 `--hero-bg` 면이다.

CSS 로드 순서(고정):

```
design_kits_lets/base.css → components.css → tokens.css → extras.css
→ frontend/src/styles/project-tokens.css   (프로젝트 토큰만)
→ frontend/src/styles.css                  (도메인 스타일만)
```

- `mobile.css`는 **로드하지 않는다** — 앱형 셸(앱바·탭바·FAB)을 쓰지 않는다(§12).
- `styles.css`는 킷 `.k-*` 위에 **여백·크기·도메인 규칙만 얹는다.** 같은 것을 다시 정의하지 않는다.
  퀴즈·진단·음성·편집·영어 블록은 이 파일 맨 아래에 있고, **그 값의 근거는 §15·§16이다**.

## 5. 다크 모드 — `data-theme` 방식

- `<html data-theme="dark">`만 바꾸면 킷의 `:root[data-theme="dark"]` 토큰 한 벌이 덮어써지고 전 화면이 따라온다.
  **컴포넌트 CSS는 손대지 않는다.** Lets는 라이트·다크 두 모드를 모두 지원하고 **기본은 라이트**다.
- `document.documentElement.style.colorScheme`도 함께 세팅해야 스크롤바·`<select>` 같은 브라우저 기본 UI까지 어두워진다(자주 빠뜨린다).
- 설정값 3종: `"light" | "dark" | "system"`, `localStorage` 저장, 초기값 `system`.
  `system`은 **계산해서 `light`/`dark`를 명시**한다 — 킷의 `prefers-color-scheme` 폴백에 맡기지 않는다(둘이 어긋나면 원인을 찾기 어렵다).
- FOUC 방지: `index.html`의 `<head>` 인라인 스크립트가 **CSS 로드 전에** `data-theme`을 선적용한다.
- 구현: `frontend/src/lib/theme.js`.

다크에서 자주 나는 사고 3가지:

- **`input`/`select`/`textarea`에 `.k-input`/`.k-select`/`.k-textarea`를 안 붙이면 그 요소만 흰 배경으로 남는다.** 가장 흔한 사고다.
- **하드코딩이 한 곳이라도 남으면 그 요소만 라이트로 남는다** — `#hex`·`rgb()`·`color-mix()`를 전수로 없앤다.
- 라이트에서 `--border`로 보이던 경계가 다크에서 배경과 붙어 **면이 사라져 보인다** → 안쪽 면을 `--surface-alt`로 한 단 낮춘다.

## 6. 3줄 병기 (일본어 문장 표기의 표준형)

컴포넌트: `.jp-sentence` / `frontend/src/components/JpSentence.jsx`

```
ここは 教室です。        ① 원문      --t-xl(22px) / var(--text)   / --font-jp
ここは きょうしつです。   ② 가나 읽기  --t-md(15px) / var(--muted)  / --font-jp
여기는 교실입니다.        ③ 한국어 뜻  --t-sm(13.5px) / var(--muted2) / 본문 폰트
```

**세 줄의 크기 차이가 이 컴포넌트의 전부다**(원칙 ④). 본문이 커지거나 작아지면 세 값을 함께 다시 잡는다 —
급간이 눌리면 "원문 / 읽기 / 뜻"이 한 덩어리로 보인다.

규칙:

- **적용 범위는 "문장 단위 콘텐츠 전부"** — 문법 예문, 회화 대사, 정리 스텝 요약 예문, 자료실 문법 상세.
- **가나 줄 생략**: 원문에 한자가 없어 읽기가 원문과 같으면(`kana === null`) ② 줄을 아예 렌더링하지 않는다.
  표 형태에서는 읽기 열에 `─`를 넣는다(유닛 어휘표·자료실 어휘표 공통).
- **문장이 아닌 단위에는 쓰지 않는다.** 한자는 음독/훈독 별도 필드(`.kv-row` 나열), 어휘는 3열 표(단어/읽기/뜻).
  단 한자의 **예시 단어**는 3줄 스택(`.kanji-word`)이고, 유닛 학습과 자료실 상세가 이걸 공유한다.
- 반응형: ≤768px에서 원문 22px → **19px**.
- **라틴 문장은 같은 컴포넌트 + `latin` 클래스**로 자형만 되돌린다(`font-family: inherit`) — 영어 과정이 쓴다(§16-4).
  영어 데이터는 `kana`가 항상 null이라 위 "가나 줄 생략" 규칙이 그대로 걸려 **자동으로 2줄 병기**가 된다. 영어용 표기 컴포넌트를 새로 만들지 않는다.

탈락한 대안 — 다시 제안하지 말 것:

| 대안 | 왜 안 되나 |
|---|---|
| 후리가나 루비 | 어절 세그먼트 데이터가 필요해 제작비가 오르고, 8~9px로 작아져 왕초보에게 안 읽히며, 줄 높이가 흔들리고 복사 시 텍스트가 섞인다 |
| 로마자 병기 | 히라가나 읽기 습관 형성을 방해한다 — N5 학습 목표와 정면으로 충돌 |

## 7. 컴포넌트 재사용 규칙

> **새 화면은 새 디자인 언어를 만드는 일이 아니라 기존 컴포넌트를 재조합하는 일이다.**

0. **먼저 킷에서 찾는다** — `design_kits_lets/클래스-목록.md`. 대개 있다. 없을 때만 도메인 컴포넌트를 만든다.
1. **같은 내용은 같은 컴포넌트로.**
   자료실 문법 상세와 유닛 학습 문법 스텝은 같은 내용이므로 `GrammarBody`를 공유한다.
   두 벌로 두면 계약이 바뀔 때 한쪽만 갱신돼 "같은 콘텐츠" 감각이 깨진다.
2. **공통 부품을 자료실별로 복제하지 않는다** (`.lv-badge`·`.applied-chip`·`.empty-block`).
3. **기존 컴포넌트를 확장하는 것이 신규 화면을 만드는 것보다 낫다.**
   예: 자료실용 404를 새로 만들지 않고 `NotFoundCard`에 prop 2개(`to`, `label`)를 추가했다(기존 호출부는 기본값으로 그대로 동작).
4. **커뮤니티에서 쓰던 것을 그대로 쓴다** — `Pagination`, 검색 입력, 정렬 셀렉트. 자료실용 변형을 만들지 않는다.
5. **반복 요소는 크기를 낮춘다**: 유닛 문법 명칭 20px → 목록 17px, 한자 배지 72px → 타일 40px, 카드 `--r-lg` → 타일 `--r`.
6. **타일에는 카드 표현을 얹지 않는다** — hover 부상(`transform`+`--sh-2`)은 "누를 수 있는 카드"의 신호다.
   타일 60개가 전부 떠오르면 신호가 아니라 소음이다. 타일은 `--border` 1px + `--surface-alt`로 조용히 둔다.

### 7-1. 층 구조 — 킷 클래스는 `ui/` 안에만 있다

킷 규약: **"React라면 클래스를 그대로 쓰지 말고 얇게 감싼다. 감싸되 스타일은 만들지 않는다."**

```
components/ui/   ← 킷 어댑터. .k-* 조립만. CSS 0줄, style={{}} 0개
components/      ← 도메인 컴포넌트. ui/를 조립 + 도메인 클래스
pages/           ← 도메인 컴포넌트를 쓴다. .k-* 를 직접 쓰지 않는 것이 원칙
```

- **감싸는 것(`components/ui/`)**: `Button` `Card`(+head/body/foot) `Chip` `Alert` `Badge`
  `Field`(+`Label`/`Input`/`Select`/`Textarea`/`Help`) `Empty` `Skeleton` `Bar` `Stat` `Table` `Modal`.
- **감싸지 않는 것**: 셸(`.k-shell` `.k-topnav` `.k-main` `.k-footer` `.k-hero` `.k-page-title`) — **`Layout` 한 곳에만 나온다**.
  유틸(`.k-flex` `.k-stack` `.k-grid` `.k-spacer` `.k-muted` `.k-mono` `.k-section`) — `className`으로 직접 쓴다.
- **활성·선택·비활성은 클래스가 아니라 속성이다**: `aria-current="page"` / `aria-selected` / `aria-pressed` / `disabled`.
  `.active`·`.on`·`.sel` 같은 클래스를 새로 만들지 않는다.
- `ui/` 안에 `style={{ color: … }}`가 한 줄이라도 생기면 **그 순간부터 킷 교체가 안 된다.**

## 8. 상태별 UI 규칙 (새 목록 화면마다 다시 적용)

### 로딩은 2종으로 구분한다

| 상황 | 처리 |
|---|---|
| **첫 로딩** | 스켈레톤. **개수는 한 화면분만** (한자 타일 12, 문법 행 6, 어휘 행 10). 60개를 다 깔면 화면 전체가 맥동한다 |
| **갱신 로딩** (페이지·필터·검색) | **기존 목록을 유지하고 흐리게** (`.list-loading` — opacity .45 + pointer-events:none). 스켈레톤으로 갈아끼우면 스크롤이 튄다 |

- 검색 디바운스(300ms) 중에는 로딩 표시를 걸지 않는다.
- **스켈레톤에 스피너를 쓰지 않는다** — 자리를 미리 잡아 레이아웃 점프를 막는 것이 목적이다.

### 부분 교체 원칙

목록 화면이 0건이거나 오류일 때 **탭·검색창·필터바·적용 칩은 절대 사라지지 않는다.**
교체되는 것은 목록 영역과 페이지네이션뿐이다 — 사용자가 조건을 고쳐 빠져나갈 수 있어야 한다.
(전체 교체는 상세 화면에서만.)

### 빈 블록 금지

활용표가 없으면 표 자리와 제목까지 통째로 렌더링하지 않는다. 예시 단어 0개면 소제목째, 예문 0개면 블록째 없앤다.
**"없음"이라고 적힌 빈 상자를 남기지 않는다.**

**열 단위로도 적용한다** — `─`만 늘어선 열은 정보가 아니라 잡음이다.

| 대상 | 규칙 |
|---|---|
| **유닛 어휘 표** | 그 유닛의 어휘가 읽기(`kana`)/발음(`ipa`·`koApprox`) **전량 null이면 그 열을 헤더째 빼고 한 열 줄인다**(입문 유닛·영어 유닛이 여기 걸린다) |
| **자료실 어휘 목록** | **적용하지 않는다.** 여러 코스가 섞인 목록에서 열을 감추면 값이 있는 다른 행의 읽기까지 사라진다 |
| 한 행이라도 값이 있을 때 | 열을 유지하고 없는 행만 `─`(§6) |

스텝·블록도 같다: 유닛의 한자가 0자면, 표현이 0개면 **그 스텝 자체를 만들지 않는다**. "아직 없어요" 안내를 만들지 않는다(§12).

### 0건 문구는 3분기

| 상황 | 문구 | 버튼 |
|---|---|---|
| 검색어 있음 | `'{검색어}' 검색 결과가 없어요` (작은따옴표 인용 — 오타를 스스로 발견하게) | [검색·필터 초기화] |
| 필터만 | `조건에 맞는 항목이 없어요` + 걸린 조건 되읽기 | [필터 초기화] |
| **조건이 하나도 없는데 0건** (자료실이 아직 비었다) | `아직 준비 중이에요` + 왜 비었는지 한 줄 | 콘텐츠로 가는 링크(예: [영어 코스 보기]) |

세 번째는 **사용자가 고칠 수 있는 게 없는 상태**라 "초기화"를 권하면 거짓 안내가 된다.
조건 0건과 구조적 0건은 반드시 다른 문구여야 한다.

**필터 칩 줄에 없는 조건이 적용 칩에는 있는 상태가 정상이다** — 주소로 들어온 값(예: 한자 자료실의 `?level=INTRO`)은
칩 목록에 선택지가 없어도 **적용 칩에 띄워 해제할 수 있게** 한다. 조용히 지우면 사용자는 왜 0건인지 알 수 없다.

### 그 밖

- **문구에 숫자를 고정하지 않는다.** "1,415개", "총 1,000자" 같은 하드코딩 금지 — 전부 API 값을 쓴다.
- 범위 밖 페이지 번호는 **조용히 1페이지**로. 경고·토스트 없음.
- 로딩 실패는 "불러오지 못했어요" + [다시 시도]. 화면이 빈 채 방치되지 않는다.

### 진도·보관함이 화면에 얹힐 때 (2026-08-14 확정)

| 규칙 | 내용 |
|---|---|
| **진도 0이면 막대를 그리지 않는다** | 빈 막대를 깔면 "안 한 일"이 강조된다. 준비중 코스도 막대 없음 |
| **진도 때문에 에러 화면을 만들지 않는다** | 진도·보관함 조회가 실패하면 **진도 없는 화면과 똑같이** 그린다(부가 정보이지 본문이 아니다). 단 **보관함 화면의 목록 실패는 예외** — 그건 본문이라 [다시 시도] 카드를 보여준다 |
| **진입 안내 띠는 한 번에 하나** | 유닛 학습 상단(`.k-alert` + 내부 `.k-flex`)에 "이어서 보고 있어요 (4/7)" **또는** "이 유닛은 마쳤어요" 중 하나만. 완료 유닛은 1번 스텝으로 열리므로 둘이 겹치지 않는다 |
| **★는 9곳이 한 컴포넌트** | 자료실 목록·상세 3종 + 유닛 학습 3스텝 + 보관함. 글리프는 텍스트라 폰트·SVG가 늘지 않고, **클릭 전파를 막아** 행 이동으로 번지지 않는다 |
| **저장 표시를 만들지 않는다** | 자동 저장(스텝 이동·진입)에 스피너·토스트가 없다. 실패해도 조용하다. **손으로 누른 것(완료 토글·★)만** 실패를 인라인 한 줄로 알리고 표시를 되돌린다 |
| **보관함 기본 탭 = 담은 것이 가장 많은 탭** | 전부 0이면 한자. 개수가 0인 탭을 먼저 보여주면 빈 화면으로 시작한다 |
| **빼기는 확인하지 않고 되돌린다** | ★를 다시 누르면 그 행이 즉시 사라지고 **그 자리에** "되돌리기" 한 줄이 남는다(토스트 아님). 되돌릴 수 없는 것만 대화상자다(§12-1) |
| **개수 0은 숫자를 감춘다** | 자료실의 [내 보관함] 링크는 0일 때 숫자를 빼고 이름만 보여준다(결핍을 강조하지 않는다 — §12) |

## 9. 주소(URL)가 목록 상태의 단일 출처

- 검색어·필터·정렬·페이지는 **쿼리스트링**에 둔다. 컴포넌트 state에 이중으로 두면 뒤로가기가 어긋난다.
  `useSearchParams` 한 곳에서 읽고 쓴다(검색 입력만 디바운스용 로컬 state, 300ms 후 `replace`).
- **기본값은 주소에서 생략한다** (`page=1`, 기본 정렬, 빈 `q`).
- 상세 → "목록으로"는 **직전 목록 주소를 그대로 복원**한다(브라우저 뒤로가기와 결과가 같아야 한다).
- **순간 상태는 주소에 넣지 않는다** — 어휘 아코디언 펼침, 유닛 학습 스텝 등.
- 필터·검색이 바뀌면 1페이지로 복귀하고, 페이지 이동 시 목록 상단으로 스크롤을 리셋한다.
- **페이지당 개수는 어떤 화면 폭에서도 바뀌지 않는다** (한자 60·문법 20·어휘 50).
  기기마다 다르면 **주소를 공유했을 때 다른 목록**이 나온다.

## 10. 반응형 브레이크포인트

**본문 폭은 `--content-max`(1200px)로 고정된다** — 화면이 더 넓어져도 본문은 커지지 않는다.
그래서 브레이크포인트는 1200px 이하에서만 의미가 있다.

| 폭 | 기준 |
|---|---|
| **≥1200px (본문 폭 최대)** | 한자 타일 6열 |
| **≤1024px** | 카드 그리드 3열→2열, 필터바 자연 줄바꿈, 한자 타일 4열. GNB는 여전히 가로 |
| **≤768px** | 카드 그리드 1열, GNB **햄버거 + 불투명 드롭 패널**, 히어로 축소(제목 24px), `.jp-sentence` 원문 22→19px, 한자 카드 1열 / 타일 3열, 어휘 표 5열→3열 + `.vocab-meta` 줄, 문법·유닛 행 2줄 배치, 스텝 바 가로 스크롤, 자료실 필터 접기 토글 `[⚙ 필터 (n)]`, 주요 버튼 `.k-btn--block` |
| **≤480px** | 한자 타일 2열, 결과 개수·적용 칩 2줄 분리, 어휘 표 폰트 축소, 상단 보조 캡션 숨김 |

**킷 버튼·입력은 `--touch`(46px) 최소 높이를 갖는다.** Halo 시절보다 커졌으므로 좁은 화면의 버튼 줄이 밀린다 —
한 줄에 3개 이상 서던 자리는 `--sm`으로 낮추거나 줄을 나눈다.

가로 스크롤 정책 — **목적에 따라 갈린다**:

- **문법 활용 규칙표(상세): 가로 스크롤 허용.** 규칙표는 **행 간 비교**가 목적이라 열이 접히면 못 쓴다.
- **어휘 표(목록): 가로 스크롤 금지, 열을 접는다.** 어휘표는 **행 단위 조회**가 목적이다.
  정보는 사라지지 않고 `.vocab-meta` 줄로 내려간다.

## 11. 접근성

- **탭 줄은 `role="tablist"`가 아니라 일반 내비게이션 링크(`<Link>`)다.** 주소가 바뀌는 페이지 이동이므로
  새 탭 열기·주소 복사가 되어야 한다.
- 어휘 표의 확장 행: `<tr>` 안에 `<button>`을 넣지 않고 **행 자체에 `role="button"` + `aria-expanded` + `tabIndex=0`**
  (Enter/Space 토글). 확장된 내용은 `aria-hidden` 처리하지 않는다(스크린리더가 읽어야 한다).
- 새 탭 링크: `target="_blank" rel="noopener noreferrer"` + **`aria-label`에 "(새 탭에서 열림)"** + 시각 예고 글리프 `.ext-mark ↗`.
- **포커스 링은 킷이 준다**(`--sh-point` / `--focus`). 우리가 다시 정의하지 않고, `outline: none`으로 지우지도 않는다.
  Tab으로 모든 버튼·링크에 링이 보여야 한다.
- **상태는 클래스가 아니라 속성으로 표시한다**: 현재 위치 `aria-current="page"`, 선택 `aria-pressed`,
  탭 선택 `aria-selected`, 비활성 `disabled`, 오류 `aria-invalid="true"`.
  접근성과 스타일을 한 번에 얻는 것이 킷 계약의 설계다.
- **모든 `<table>`은 `.k-tablewrap` 안에 넣는다** — 없으면 좁은 화면에서 페이지가 가로로 터진다.

## 12. 만들지 않기로 한 것

| 만들지 않는 것 | 이유 |
|---|---|
| **오버레이 · 바텀시트 · 정보/폼 모달** | 학습·열람을 중단시키지 않는다(기획 원칙). 킷에 `.k-modal`이 있어도 우리는 **확인 대화상자에만** 쓴다 — 아래 12-1 |
| **하단 탭바(모바일)** | 내비게이션 언어를 하나 더 만드는 일이다. GNB 햄버거로 충분. **그래서 킷의 `mobile.css`를 로드하지 않는다**(§4) |
| **레벨 배지의 색 구분** | 4색을 넣으면 타일 60개에 색점이 60개 찍혀 "강조는 인디고 하나"(원칙 ②)가 깨지고, 색-레벨 대응을 새로 외워야 한다. `.lv-badge`는 단색이다 |
| **필터 칩 선택 상태의 강조 면 남용** | 선택은 `--point-soft` + `aria-pressed="true"` 하나로 끝낸다. **오렌지(`--point-2`)를 선택 표시에 쓰지 않는다** — 오렌지는 "새로 생긴 것" 전용이다(§3-1 C) |
| **"전체" 칩** | 선택 해제 = 전체다. 칩은 그룹 내 OR, 그룹 간 AND |
| **정렬을 칩으로** | 정렬은 택일이라 복수 선택 언어(칩)와 섞이면 오해된다 → 정렬은 셀렉트, 필터는 칩 |
| **없는 기능에 대한 사과 문구** | "획수 정보는 아직 없어요" 같은 안내는 결핍을 부각한다. 확장은 자리를 비워 두는 게 아니라 **구조로 확보**한다 — 한자 상세는 `.kv-row` 나열이라 나중에 행 2개만 추가하면 되고, 자료실 탭도 `.k-tabs` 기반이라 4번째 탭이 붙어도 안 깨진다 |

### 12-1. 유일한 예외 — 확인 대화상자 `.confirm-dialog` (2026-08-14 개정, senior-dev 승인)

**개정한 이유(2026-08-14, Halo 시절)**: 원래 금지의 근거는 "모달 = 반투명 유리 → 원칙 ③(blur는 헤더에만)과 충돌"이었다.
**blur를 쓰지 않는 대화상자는 그 근거에 걸리지 않는다.** 근거가 닿지 않는 곳까지 금지가 뻗어 있었던 것이다.
그리고 되돌릴 수 없는 삭제(보관함 전체 비우기·학습 기록 초기화·브라우저 기록 지우기·회원 탈퇴)를 인라인 확인으로 처리하면,
사용자는 "되돌릴 수 없다"는 사실을 **누른 뒤에** 알게 된다.

**Lets 전환 후에도 이 예외는 그대로다.** 근거가 "유리"에서 "학습을 중단시키지 않는다"로 바뀌었을 뿐,
되돌릴 수 없는 삭제만 확인받는다는 결론은 같다. 킷이 `.k-modal`을 제공한다고 해서 쓰임이 넓어지지 않는다.

**허용 조건 — 전부 만족할 때만 (하나라도 어기면 §12의 금지로 되돌아간다)**

| # | 조건 |
|---|---|
| ① | **컴포넌트는 `components/ConfirmDialog.jsx` 하나뿐이다.** 화면마다 다른 대화상자를 만들지 않는다 |
| ② | **`backdrop-filter` 금지.** 딤은 불투명도만 있는 단색(킷의 `--overlay`)이다. 패널은 `--surface` **불투명** |
| ③ | **강조 0개.** 확인 버튼은 `.k-btn--primary`가 아니라 `.k-btn--danger`다 — 파괴적 동작을 주 버튼으로 만들면 "권장 행동"으로 읽힌다 |
| ④ | **되돌릴 수 없는 파괴적 동작에만.** 되돌릴 수 있는 것(별 빼기 등)은 대화상자가 아니라 **되돌리기 한 줄**로 처리한다 |
| ⑤ | **`<dialog>` + `showModal()`** 을 쓴다 — ESC 닫기·포커스 트랩·`aria-modal`이 공짜다. div로 흉내 내지 않는다 |
| ⑥ | **기본 포커스는 취소, 취소가 오른쪽.** 실수로 누르기 쉬운 자리에 파괴적 동작을 두지 않는다 |
| ⑦ | **본문의 숫자는 실제 값**이다("한자 34개를 모두 뺄까요?"). 하드코딩 금지 |

**여전히 금지인 것** (이 예외가 열어 준 것이 아니다):

- 정보를 보여 주는 모달, 입력 폼 모달, 바텀시트, 오버레이 내비게이션·검색, 이미지 라이트박스
- 토스트·인라인 안내로 될 일을 대화상자로 올리는 것 (학습·열람을 중단시키지 않는다는 기획 원칙)
- 대화상자 안의 강조 면·유리(blur)·2단 스크롤
- 대화상자로 **취소 가능한** 동작을 확인받는 것 (④의 반대)

> 이 예외를 더 넓히려면(예: 폼 모달) **여기 적힌 근거부터 반박해야 한다**(`08_결정기록.md` 서문 규칙).

**폼 모달 금지가 실제로 어떻게 풀렸나**: 관리자 편집은 모달 대신 **원본 블록 바로 아래 인라인 펼침**으로 만들었다(§15-4).
금지가 기능을 막은 게 아니라 더 나은 배치(변경 전 값을 보면서 고치기)를 강제했다. 폼이 필요해지면 **먼저 인라인을 시도한다.**

새 화면을 구상할 때 가장 빨리 방향을 잡아주는 목록이다.

| 탈락 시안 | 왜 안 되나 |

| Blueprint (다크 + 모노 + 고밀도) | 기본은 밝고 반듯하게. **다크는 옵션이지 정체성이 아니다** |
| Paper (크림 + 명조) | **세리프를 쓰지 않는다** |

| Console (초고밀도) | **빽빽하게 채우지 않는다.** 여백이 재료다 |
| Warm (따뜻한 파스텔) | **색온도는 차가운 쪽**(인디고·연보라) |
| Bento (비균일 타일) | **균일한 카드 그리드**를 유지한다 |

한 줄로: **밝고 · 차갑고 · 반듯하고 · 균일하고 · 1px 선으로 구조를 만드는** 쪽.

> Lets 킷 자체의 "피할 곳"도 지킨다: **고밀도 관리자 표 · 감성 브랜드 랜딩 · 처음부터 어두운 화면.**
> 새 화면이 이 셋 중 하나로 흘러가면 킷을 벗어난 것이다.

## 15. 학습 도구 화면 규칙 (퀴즈 · 실력 진단 · 음성 · 편집 모드)

> 새 화면에 이 도구를 붙일 때 여기 적힌 것 말고 새 언어를 만들지 않는다.
> ⚠️ **여기는 보여주는 방식만 적는다.** 문항을 어떻게 만들고(유형 8종·오답 풀·4지선다), 진단 계단·추천을 어떻게 판정하고, 음성이 어떻게 동작하는가는 **`설계/09_학습도구_동작규칙.md`이 원본**이다. 생성 규칙과 화면 규칙을 두 곳에 적지 않는다(08 C-11).


### 15-1. 퀴즈는 한 벌뿐 — `QuizRunner`

**진입이 셋(유닛 확인 문제 · 자료실 퀴즈 · 실력 진단)이지만 카드는 하나다.** 다른 것은 프리셋뿐이다.
시작 → 문제 → 결과는 **한 주소 안의 상태 전환**이다(라우트를 쪼개지 않는다 — 결과는 저장되지 않으므로 되돌아갈 주소가 없다).

| | 유닛 확인 문제 | 자료실 퀴즈 | 실력 진단 |
|---|---|---|---|
| 문항 수 | 유닛이 정한 상한 고정 | 칩으로 택일(기본 10) | 단계당 고정 수, 계단 수에 비례 |
| 즉시 채점 표시 | O | O | **X** |
| 결과 primary | 다음 유닛(마지막이면 코스 완료 분기) | 자료실로 돌아가기(조건 복원) | 추천 코스 시작하기 |

**카드 규칙**

- `.quiz-card` = 기성 `.k-card` + **폭 640px 중앙**. 읽는 면은 `--surface` 불투명.
- 진행 줄 `.quiz-progress`: "{현재} / {전체} · 맞은 개수 {n}", `--muted` `--t-sm`, **`tabular-nums`**
  (3/10 → 4/10에서 숫자 폭이 흔들리면 줄이 떨린다).
- 지문 `.quiz-prompt`: 문장형은 `.jp-sentence` 원문과 같은 급(`--t-xl`, ≤768px 19px),
  **한자 1~2자는 `.glyph`로 64px**(≤768px 48px) 가운데 정렬. 빈칸은 `＿＿` 글리프 — 새 장식을 만들지 않는다.
- **보기는 세로 스택**(`.quiz-choice`, 폭 100% 좌정렬, `--r`). 4개는 **반복 요소라 강조 면 금지**.
  hover는 글자색 `--point`(칩과 같은 문법).
- **채점 후 상태**: 정답 `--ok-soft`+`--ok-text`, 고른 오답은 `--err-soft`+`--err-text`
  (`.k-alert--err`와 **같은 식**. 순수 `--err`는 틴트 위에서 채도가 튄다).
  **`color-mix()`로 틴트를 계산하지 않는다 — 킷이 `-soft`/`-text` 쌍을 이미 준다.**
  나머지는 `disabled` + opacity .55. **정오 규칙은 `:disabled` 뒤에 와서 opacity를 되돌린다.**
- **색만으로 정오를 전달하지 않는다** — `.quiz-verdict`(`role="status"`) 한 줄이 "정답/오답"을 글자로 말한다.
- **정오 연출 금지.** 흔들림·번쩍임·효과음 없음. transition은 `color`·`box-shadow`뿐 — 조용한 90%다.
- 근거 `.quiz-evidence`: `--surface-alt` 박스(`--r`). 내부는 전부 기성(`.kv-row`·`.kanji-word`·`.jp-sentence`)이고
  **여백만 맞춘다**. 자료실 링크는 여기 넣지 않는다(결과 화면의 몫).
- 결과: 점수는 기성 `.k-stat`을 **카드 안에서** 쓰되 면을 `--surface-alt`로 낮추고 **테두리를 끈다**
  (surface 위 surface는 평평해 보이고, 카드 속 카드는 카드가 아니다 — §7-6과 같은 판단. 선 위에 선을 겹치지 않는다 — §2 보조규칙).
  정오 목록 `.quiz-result-row`는 행 구분선 `--border` 1px.
- **결과의 자료실 링크는 진입과 무관하게 전부 새 탭**(`.ext-mark ↗`). 같은 탭으로 나가면 결과 상태가 소멸한다.
- 버튼 줄 `.quiz-result-actions` 하나를 시작·문제·결과·에러·0문항 카드가 **전부 공유**한다. ≤768px에서 세로 100%.
- 카드 안의 `.k-stat`·표·근거 박스는 **hover 부상을 쓰지 않는다**(`--hover` 금지) — 누를 수 있는 것이 아니다.
- **"결과는 저장되지 않아요" 한 줄**(`.quiz-note`, `--muted2`)은 결과 화면에 항상 있다.
  여기에 **로그인 유도를 붙이지 않는다** — 로그인해도 저장되지 않으므로 거짓말이 된다.

**자료실 진입 버튼**(`.quiz-entry`)은 `.result-bar` 오른쪽 끝에 붙는다 — 결과 개수·적용 칩과 같은 줄에 서야
**"이 개수·이 조건이 곧 출제 범위"** 가 배치로 읽힌다. `.k-btn--secondary`이지 primary가 아니다(목록 화면의 주인공은 목록이다).
범위가 최소 문항 수에 못 미치면 `disabled` + `.quiz-entry-hint` 한 줄로 사유를 말하고, **0건 화면에서는 버튼째 미렌더**한다
(이미 0건 안내가 조건 수정을 권하고 있다 — 같은 말을 두 번 하지 않는다).

### 15-2. 실력 진단은 "머무는 곳이 아니라 지나가는 문"

- **페이지 제목도 히어로도 없다.** `.diag-wrap`(640px 중앙) 한 단뿐. GNB에 메뉴로 넣지 않는다 —
  진입은 배너뿐이고, 그래서 이 화면의 인디고 강조 면은 0개다(§3-2).
- 진입 배너는 **히어로 바로 아래**(`.k-alert` + 내부 `.k-flex`, 강조 0). "학습 시작(기본값) ↓ 그래도 모르겠으면 물어보기(보조)"라는
  위계가 배치 순서 그대로 읽힌다. **히어로 안에 두 번째 CTA를 만들지 않는다.**
  상단 안내 띠는 여전히 **한 번에 하나** — 코스 목록에서는 기존 시작 안내 띠에 병합한다.
- **진행 표시는 계단이다**: "{레벨} 단계 · {n}번째 문제". **전체 분모를 쓰지 않는다** — 총 문항이 가변이라 "5 / 12"는 거짓 약속이다.
  최대 문항 수는 시작 화면이 이미 말했고, 그 숫자는 **계단 수에서 계산**한다(상수로 되돌리지 않는다).
- **정오를 숨기는 게 아니라 만들지 않는다** — 진단 문제 화면에는 `.quiz-verdict`·`.quiz-evidence`·"맞은 개수"가
  **DOM에 없다**. CSS로 숨기면 "있는데 안 보이는 것"이라 계약과 다르다.
- 결과: 추천 한 줄 `.diag-headline`이 화면에서 가장 큰 글자(`--t-2xl` 급, `--display-tracking`). 코스명·레벨은 **API 값**이다.
  근거 표는 기성 `.k-tablewrap` + `.k-table` 3열(레벨·정답 수·판정), **진행한 단계만 행으로**(빈 블록 금지).
  숫자 열은 `.k-num`(`tabular-nums`).
- 실패했을 때의 주 버튼은 **학습으로 가는 길**이다(`[일단 {첫 코스}부터 시작하기]`가 primary, [다시 시도]는 보조).
  진단은 목적이 아니라 수단이다.
- 단계 전환 로딩은 **문제 카드와 같은 자리·같은 높이의 기성 스켈레톤**을 쓴다. 진단 전용 스켈레톤을 만들지 않는다.

### 15-3. 음성(TTS) — 줄 끝에 붙되 줄을 밀지 않는다

- **재생 버튼은 `.tts-btn` 하나뿐이다.** 붙는 자리가 몇 곳이든 컴포넌트는 하나다.
  28px 원형 + `flex: 0 0 28px` **고정** — 3줄 병기의 줄 높이가 흔들리지 않게 하는 값이다.
- **아이콘은 이미 로드된 Material Icons 글리프를 재사용**한다(대기 `volume_up` / 재생 중 `stop`).
  **새 아이콘 폰트·SVG를 들이지 않는다**(★가 텍스트 글리프인 것과 같은 원칙).
- 상태: 대기 = `--muted`, **배경 없음**(문장을 밀어내지 않는다) → hover `--point` →
  재생 중 `--point-soft` 배경 + `--point` + **`aria-pressed="true"`**. 강조 면·그림자 금지(반복 요소다).
- 같은 버튼이 재생/정지 토글이고, **클릭 전파를 막는다**(행 아코디언·행 이동으로 번지지 않게 — ★와 동일).
- 지금 읽는 대사 줄은 `.dialog-line.playing` — `--point-soft` **불투명** 배경.
- **붙이지 않는 곳**: 활용표, 한자 글자 자체. 낱자 음성은 학습에 쓸모가 없다.
- **속도는 칩 하나다** — 라벨 "느리게", 켜짐은 `.k-chip` + `aria-pressed="true"`. 2단계에 셀렉트·슬라이더는 과하다.
  **화면당 1개**, 눈에 띄지 않는 우측 끝(`unit-topbar` / `RefTopbar` / 표 위 / 결과 카드 캡션 줄).
  **선택은 localStorage에 전역 저장**되어 화면을 옮겨도 유지되고, **다음 재생부터** 적용된다.
  전용 클래스를 만들지 않는다 — 기성 `.k-chip` 그대로다.
- 캡션 줄에 컨트롤을 얹을 땐 `.step-caption.row-caption`(회화 스텝·결과 카드 공용).
- **음성이 없는 기기에서는 재생 버튼·전체 재생·속도 칩을 전부 미렌더하고 안내도 하지 않는다.**
  버튼이 전부 **줄 끝 append**라 미렌더 시 레이아웃이 음성 없는 화면과 100% 같다 — 이것이 자리 선정의 숨은 기준이다.
- 재생 실패(음성은 있는데 소리가 안 남)는 그 패널 상단 `.k-alert--warn` 한 줄, **화면당 1회만**. 닫기 버튼 없음.
- 화면·스텝을 옮기면 재생을 멈추고 시각 상태(`playing`·`aria-pressed`)도 함께 해제한다.

### 15-4. 편집 모드 — **로컬 전용 도구다**

- **켜지는 조건은 서버 상태 응답 하나뿐**이고, 꺼진 환경에서는 띠·[고치기]·패널이 **전부 미렌더**되어
  화면이 운영과 100% 동일하다. 상태 조회 실패 = 꺼짐으로 취급한다. 로딩·스켈레톤에도 [고치기]를 그리지 않는다.
- **앱에는 넣지 않는다.**
- 편집 모드 띠 `.editor-mode-bar`: **GNB보다 위**, `--warn-soft` 면 + `--warn-text` 글자, 얇은 한 줄, 중앙 정렬.
  **sticky 아님** — GNB만 sticky다. 겹쳐 붙는 층을 두 개 만들지 않는다. "상시"의 뜻은 **모든 화면에 렌더**다.
- 진입점은 **고칠 대상 블록의 제목 줄 우측**([고치기]는 `.k-btn--ghost .k-btn--sm`). 대상이 있는 자리에만 있다.
- **편집 패널은 모달이 아니라 원본 블록 바로 아래 인라인 펼침**이다(`.editor-panel`).
  §12가 입력 폼 모달을 금지하기 때문만이 아니라, **변경 전 값을 보면서 고쳐야** 하기 때문이다 — 대조가 오탈자 수정의 본질이다.
  **한 화면에 패널은 1개**, 열려 있는 블록의 [고치기]는 숨긴다.
- **패널 밖 클릭으로 닫지 않는다.** 인라인에서 밖 클릭은 스크롤·본문 클릭과 구분되지 않아 입력을 날린다.
  닫기는 [취소]·[✕]·ESC뿐이고, **고친 내용이 있으면 `ConfirmDialog`로 확인**한다(§12-1 ④의 정당한 적용 — 입력 폐기는 되돌릴 수 없다).
- **고칠 수 없는 값은 입력칸을 만들지 않는다**(제목에 읽기 전용으로만 보인다). 비활성 input은 "왜 안 되지"라는 질문을 만든다.
- 검증은 **어긴 칸 바로 아래 `.k-help--err` + 입력에 `aria-invalid="true"` + [저장] 비활성**. 서버가 400을 줘도 **같은 자리·같은 형식**으로 표시한다.
- 저장 실패·404는 **패널을 닫지 않고 입력값을 보존**한 채 패널 상단 `.k-alert--err`로 알린다.
  변경이 없으면 요청 없이 패널만 닫는다.
- 저장 결과는 `.k-alert--ok` + **`.editor-diff`(`--surface-alt` + `--font-mono`)** — 복사 대상임이 모양으로 읽힌다.
  복사 성공은 **버튼 라벨을 2초간 바꿔** 알린다(토스트 금지).
- 반복 행(`.editor-row`)은 좁아지면 **세로 스택**이다. 규칙표는 가로 스크롤을 허용하지만(§10)
  **편집 칸은 행 간 비교가 목적이 아니다** — 같은 표라도 목적이 다르면 정책이 갈린다.

## 16. 과정별 화면 규칙 (일본어 · 영어)

> 영어 과정은 **뼈대**다. 화면 셸은 일본어 것을 그대로 쓰되, 아래 다섯 가지가 갈린다.

### 16-1. ⚠️ 영어 화면에는 학습 도구를 켜지 않는다 (2026-08-25 판정 — `08 C-14`)

**영어 화면에는 `.quiz-*`·`.tts-*`·`.editor-*` 요소가 하나도 없다.** 확인 문제 스텝도, 재생 버튼도, 속도 칩도 없다.

- 근거: 영어는 콘텐츠가 없는 뼈대다. **미완성 학습 도구를 먼저 켜면 일본어 조판(`--font-jp`)·일본어(ja) 음성·
  빈 근거 상자를 영어 학습자에게 제품으로 보여주게 된다.** 도구는 콘텐츠가 찬 뒤에 켠다.
- 한 번 켰다가 되돌린 적이 있다(테스트가 초록이라 아무도 의심하지 않았다). **다시 붙이지 마라** —
  붙이려면 영어 콘텐츠가 먼저 차야 하고, 그때 일본어와 **같은 틀로 함께** 얹는다.
- 파생 규칙: 영어 회화 스텝의 캡션 줄은 `.step-caption` 단독이다(`.row-caption`이 아니다 — 얹을 컨트롤이 없다).
- **진도는 학습 도구가 아니다.** "어디까지 봤나"의 기본 기록이므로 영어 유닛에서도 그대로 동작한다.

### 16-2. 레벨 표기 — 코드는 화면에 나오지 않는다

**`levelCode`는 필터 값(요청 파라미터)으로만 쓰고, 사람이 읽는 문구는 언제나 표시 맵을 거친다.**

| 과정 | 화면 문구 |
|---|---|
| 일본어 | `입문` `N5` `N4` `N3` `N2` `N1` |
| 영어 | `코스 1` … `코스 5` (그룹 라벨도 **"레벨"이 아니라 "코스"**) |

- `N5`가 화면에 보이는 건 코드라서가 아니라 **JLPT 공인 표기라 학습자가 이미 아는 말**이기 때문이다.
  `INTRO`·`E1` 같은 DB 값은 아무도 본 적이 없다 → 코스를 부르는 이름 그대로 쓴다("입문", "코스 1").
  자료실 필터는 **"어느 코스에서 배운 항목인가"** 를 고르는 장치이므로 코스 이름이 정확한 말이다.
- **맵은 코드 → 문구 단방향이다.** 문구에서 코드를 되만드는 역변환·문자열 가공 함수를 만들지 않는다.
- **맵에 없는 코드는 코드를 그대로 표시**한다. "알 수 없는 레벨" 같은 사과 문구를 만들지 않는다(§12).
- **적용처 네 곳을 한 군데도 빠뜨리지 않는다**: ① 필터 칩 ② 적용 칩 ③ 0건 안내의 조건 되읽기 ④ `.lv-badge`.
  넷이 어긋나면 "고른 것"과 "행에 붙은 것"이 다른 말이 되어 같은 조건으로 읽히지 않는다.
- **영어에는 `levelLabel`을 쓰지 않는다.** 코스 상세 h1·완주 안내·`WhereLearn`은 **코스명 단독**이고,
  일본어가 쓰는 `{title}({levelLabel})` 괄호를 붙이지 않는다. 코스 카드도 레벨 라벨 없이 `코스 {n}`이다.
- 칩 순서는 **학습 순서 고정**(입문 → N5 → … → N1 / 코스 1 → 코스 5). 정렬 셀렉트와 무관하다.
- **선택지에서 뺀 것과 거부하는 것은 다르다** — 한자 자료실에 `입문` 칩이 없는 것은 그 탭의 사실이고,
  **설명하지 않는다**(§12). 주소로 들어오면 §8의 적용 칩 규칙대로 표시해 해제하게 한다.
- 자료실 탭도 `.k-tabs` 기반이라 **4번째 탭이 붙어도 안 깨진다**(확장은 구조로 확보한다 — §12).

### 16-3. 영어 자료실은 3탭, 기본 탭은 **표현**

- 탭 = **표현 / 문법 / 어휘**. **한자 탭이 없고**, `/en/library`는 **표현 탭으로** 보낸다.
- **"한자"라는 낱말이 영어 화면에 한 번도 나오지 않는다** — 한자가 있던 자리는 전부 **"표현"**이다
  (유닛 스텝, 코스 상세 집계 줄, 유닛 행 메타, 자료실 탭).
- 페이지 아바타(`.k-avatar`) 글리프는 `abc`(일본어 `辞` 자리·크기 그대로).
- **정렬 셀렉트를 렌더하지 않는다** — 영어에는 가나순 같은 제2 정렬이 없다.
  선택지가 하나뿐인 셀렉트는 조작할 것이 없으므로 `result-bar`의 `· 학습 순서` 표기만 남긴다.
  (일본어 자료실의 정렬 셀렉트는 그대로다 — 두 과정의 화면이 갈리는 유일한 지점이라 회귀 시험 대상이다.)
- 품사 필터는 **그 과정의 품사만** 노출한다. 일본어 7종(い·な형용사 포함)과 영어 7종(전치사·접속사·표현 포함)을 섞지 않는다.
- 영어 보관함(★)은 아직 열지 않았다 — **열 때 유닛·자료실 여러 곳에 한 번에 붙인다**(한 곳씩 늘리면 규칙이 흩어진다).

### 16-4. 영어 표기 — 라틴 자형과 발음

- **영어 문장에 `--font-jp`를 씌우지 않는다.** 기존 표기 컴포넌트에 `latin`을 얹어 자형만 본문 폰트로 되돌린다(§6).
  영어 데이터는 `kana`가 null이라 **2줄 병기(원문 / 한국어 뜻)** 가 자동으로 된다.
- **발음은 `ipa`와 한국어 근사 표기 둘 다**, 없으면 `─`(가나 규칙 그대로).
  어휘 표는 **3열을 유지**하고 읽기 열 자리의 한 셀에 **두 줄**로 넣는다 — **4열로 늘리지 않는다.**
  둘 다 없으면 줄째 생략, 전량 없으면 열째 생략(§8).
- **표현 카드 `.expr-card`는 세로 1열 스택**이다. 한자 타일처럼 격자로 깔지 않는다 —
  표현은 가로로 길고 예문이 딸려 있어 2열로 쪼개면 줄바꿈이 지저분해진다.
  구성: 표제 20px → 발음 한 줄(`{ipa} · {근사표기}`) → 뜻 → 용법(있을 때만) → 예문 박스(`--surface-alt`, 0개면 박스째 생략).
  **강조 면·hover 부상 금지**(6~10장 반복이다 — §7-6과 같은 이유).
- 표현 카드를 **한자 카드로 대신하지 않는다**(한자 카드는 글자 1자를 큰 배지로 세우는 구조라 배지 자리가 빈다).
  **문법 블록으로도 대신하지 않는다**(문법은 유닛당 2~3개에 설명이 길고, 표현은 6~10개라 훑는 목록이어야 한다).
  자료실 표현 상세는 문법 상세와 같은 골격에 **같은 `.expr-*`를 재사용**한다(같은 내용 = 같은 컴포넌트, §7-1).
- 영어 원문은 그대로 두되 **설명·라벨·안내는 전부 한국어**다(학습자 언어는 한국어다).
- **문장 안에 코스명·닉네임이 들어가는 자리는 조사 처리 함수를 거친다**("일상 말하기**은** 준비하고 있어요"가 나오면 안 된다).
- 막다른 화면을 만들지 않는다 — 준비중 카드·404의 "돌아갈 곳"은 **그 과정 안**이어야 한다.
  일본어 코스로 고정된 링크를 영어 화면에서 그대로 쓰면 과정을 배신한다. 같은 이유로 **GNB·와일드카드 404도 경로의 과정을 따른다.**

## 17. 계정 화면 규칙 (마이페이지 · 프로필 · 비밀번호 · 탈퇴)

> 계정 화면의 **동작·검증 규칙은 `설계/04 §4-1`(계약)** 이 원본이다. 여기 적는 것은 **보여주는 방식**뿐이다.
> 문구 목록(로그인 방식 라벨 등)은 **여기에도 04에도 두지 않는다** — 값의 단일 출처는 `hooks/useAccount.js`의 라벨 맵이다.
> 문구를 문서로 복사하면 코드와 문서가 조용히 갈린다(08 C-11).

### 17-1. 못 하는 일은 **회색 버튼이 아니라 미렌더**

소셜 계정에는 [비밀번호 변경]을 **아예 그리지 않는다.** 비활성 회색 버튼은 "언젠가 되는 것"으로 읽혀
사용자가 왜 안 되는지 찾게 만든다. 분기의 근거는 **`passwordChangeable` 플래그 하나**이고(04 §2-1),
화면이 `provider === "LOCAL"`을 직접 해석하지 않는다. 대신 **왜 없는지**를 한 줄 안내로 남긴다
("○○ 계정으로 로그인하고 있어요. 비밀번호는 ○○에서 관리해요").
같은 판단이 **0인 값**에도 적용된다 — 지울 것이 없으면 [학습 기록 초기화]를 그리지 않는다(08 C-12 ①).

### 17-2. 오류는 **원인이 있는 자리**에 붙인다

| 오류 | 표시 자리 |
|---|---|
| 특정 입력의 문제(닉네임 중복·비밀번호 불일치·현재 비밀번호 틀림) | **그 필드 아래** `.k-help--err` + `aria-describedby` + 입력에 `aria-invalid="true"` |
| 요청 전체 실패(네트워크·5xx) | 폼 상단 `.k-alert--err` 한 줄 |
| 서버 검증 목록(400 `errors[]`) | **메시지만** 나열한다 — 필드 변수명(`username:`)을 사용자에게 보여주지 않는다(2026-08-25 판정 B-L5) |

### 17-3. 되돌릴 수 없는 것은 **세 번 확인하고, 빨갛게 하지 않는다**

탈퇴는 ① 본인 확인 입력 ② "위 내용을 확인했어요" 체크 ③ 최종 모달 — 셋을 다 지나야 실행된다.
버튼은 구분선 아래 **danger-zone**에 떼어 놓되 화면을 빨갛게 물들이지 않는다. 겁주는 화면이 아니라 **되돌릴 수 없다는 사실**이 방어선이다.
확인 문구는 **지워질 것이 실제로 있을 때만** 수를 말한다 — "완료한 0개 유닛과 보관함 0개가 지워져요"는 판단에 도움이 되지 않는다(08 C-12 ①).

### 17-4. 로그인 유도는 **원래 자리로 돌아온다**

로그인 화면으로 보내는 모든 진입점은 복귀 주소를 함께 넘긴다(`state.from`). 끝나면 그 자리로 되돌린다 —
보관함에서 유도한 로그인이 홈에서 끝나면, 방금 담은 것을 사용자가 다시 찾아가야 한다.
SPA 안의 이동은 항상 라우터 링크다(`<a href>`는 화면을 통째로 새로 그린다).

## 18. 화면별 절을 두지 않는 이유

코스 상세·유닛 학습·정리/복습 같은 **화면 단위 절은 만들지 않는다.**
그 화면들이 쓰는 것은 §7(컴포넌트 재사용)에 있는 부품이고, 화면별 절을 만들면 같은 규칙이 두 곳에 생겨 갈린다(08 C-11).
화면 고유의 판단이 필요했던 것들은 이미 **결정으로** 남아 있다 — 0인 집계 숨김(08 C-12 ①),
영어 유닛의 학습 도구 미노출(C-14, §16-1), 학습 도구의 동작(`설계/09`).

**새 화면을 만들 때 순서**: **킷 `클래스-목록.md`에서 `.k-*`를 찾는다** → 없으면 §7의 도메인 부품을 찾는다 →
없으면 §2~§6의 토큰으로 조립한다 → 그래도 새 언어가 필요하면
**그때 결정으로 남긴다**(08). 화면마다 절을 늘리는 것은 마지막 수단이다.

## 19. 이 제품이 추구하는 화면 — 사용자 취향 기준

> 2026-09-09~10 코스 목록(`/courses`)을 사용자와 한 줄씩 맞춰 가며 **드러난 취향**을 규칙으로 옮긴 것이다.
> 그 화면의 이력이 아니라 **다른 화면에도 그대로 적용하는 기준**이다.
> §1~§18이 "이 킷을 어떻게 쓰나"라면, 여기는 **"이 사람이 무엇을 좋아하나"**다.
> 새 화면을 다듬을 때 §19-8 체크리스트부터 훑는다.

### 19-1. 한 줄로 — 차분하고 균일하게, 대신 위계는 분명하게

여섯 번의 요구를 관통하는 기준이다:

- **화려한 것보다 정돈된 것.** 강조는 아껴서 한 곳에만.
- **한 장만 튀는 것을 싫어한다.** 같은 종류는 같게 보여야 한다.
- **대신 무엇이 제목이고 무엇이 내용인지는 한눈에** 갈려야 한다.
- **군더더기는 뺀다.** 같은 말을 두 번 하지 않는다.
- **줄은 칼같이 맞는다.** 어긋난 줄을 "지저분하다"고 느낀다.

### 19-2. 읽히는 것이 먼저다

> *"컨텐츠내용도 잘 읽히면서 전체적으로 눈에 확 들어오도록"*

**읽으라고 있는 글이 화면에서 가장 잘 읽혀야 한다.** 당연해 보이지만 기본값은 자주 반대다 —
코스 카드는 제목이 본문과 같은 크기(15px)였고, 정작 내용이 13.5px에 흐린 회색이었다.

**세 단으로 벌린다. 굵기는 1단에만 쓴다.**

| 단 | 무엇 | 크기 | 굵기 | 색 |
|---|---|---|---|---|
| 1 | 제목 | `--t-xl` | `--w-heavy` | `--text` |
| 2 | **내용** — 읽어야 하는 것 | `--t-md` | 기본 | `--text` |
| 3 | 라벨·부가 정보 | `--t-sm`~`--t-md` | `--w-bold` | `--muted` |

- **2단과 3단은 크기를 같게 둬도 된다.** 라벨을 작게까지 줄이면 한 줄 안에서 두 번 꺾여 산만하다 — 굵기와 색으로만 가른다.
- **보조 텍스트의 최소선은 `--muted`다.** `--muted2`는 회색 면 위에서 대비가 약 2:1까지 떨어져 **배경과 같은 색으로 보인다.**

### 19-3. 면은 색으로 구별한다 — 선만으로는 부족하다

> *"바깥 전체 배경색이랑 이거의 배경색이 같음 둘다 흰색"* / *"단순히 파란색 테두리가 아니라 이 카드의 배경색이 있었으면"*

킷 기본값은 페이지와 카드가 **둘 다 `#ffffff`**라 1px 선 하나로 버틴다. 이 취향에는 부족하다.

| 면 | 토큰 | 쓰임 |
|---|---|---|
| 페이지 | `--bg` | 바탕은 흰색 그대로 |
| **카드** | `--surface-alt` | 내용이 얹히는 판 — **회색** |
| 카드 속 인셋 | `--surface` | 진도 막대 트랙, 중립 배지 |
| 비활성 | `--bg-sunken` | 들어갈 수 없는 것은 **눌러** 둔다 |

**강조색 면(`--point-soft`)도 대 봤지만 회색을 골랐다.** 연보라는 안내 띠가 이미 쓰고 있어
카드까지 같으면 역할이 섞인다 — **면 색은 역할당 하나씩** 배정한다.

### 19-4. 강조는 한 곳에만, 나머지는 같게

> *"입문만 다른색으로하는거 말고 다 똑같은색으로 하자"* / *"입문 카드 원판 주황색 없애는걸로"*

시작점 카드에 면 색·테두리·주황 번호판까지 세 겹으로 강조를 줬더니 **그 한 장만 튀어** 오히려 거슬렸다.
지금 시작점을 알리는 것은 **배지 문구 하나뿐**이다.

- 같은 종류(카드·행·칩)는 **면과 크기를 같게** 둔다.
- 강조가 필요하면 **한 가지 수단만** 쓴다(색 *또는* 테두리 *또는* 배지).
- ⚠️ **강조에 hover와 같은 값을 쓰지 않는다.** 시작점 카드에 hover 그림자(`--sh-2`)를 줬다가
  **그 카드만 hover 반응이 사라질** 뻔했다 — 강조는 색으로, 눌림 신호는 그림자로 나눈다.

### 19-5. 줄이 맞아야 깔끔하다

> *"높이가 안 맞아서 지저분"* / *"메뉴목록이 본문이랑 왼쪽 위치가 안맞음"*

"지저분하다"는 대개 글자가 아니라 **줄이 어긋난 것**이다. 네 곳을 본다:

1. **가변 길이는 한 블록이 흡수한다** — 카드마다 글이 1~3줄로 달라지면 그 아래 요소가 제각각 높이에 놓인다.
   글을 자르지 말고 가운데 블록에 **`flex: 1`**을 줘서 아래 요소가 **바닥에서 같은 거리**에 오게 한다.
2. **글리프와 글의 높이를 맞춘다** — 40px 아이콘 옆 83px 글 블록은 아이콘이 떠 보인다. 크기를 가깝게 맞추고 세로 가운데로.
3. **죽은 여백을 찾는다** — 킷 `.k-page-desc`의 아래 여백은 헤더 안에서 **블록 높이만 부풀린다**(헤더가 이미 그 여백을 갖는다).
4. **헤더와 본문의 왼쪽 선을 맞춘다** — 헤더는 화면 끝, 본문은 `--content-max` 가운데 기준이라 넓은 화면일수록 어긋난다.
   띠(배경)는 화면 끝까지 두고 **안쪽 여백만** 본문 선에 맞춘다. `100vw`가 아니라 **`100%`** — `vw`는 스크롤바 폭을 포함한다.

**라벨과 내용은 줄을 나눈다.** 붙여 두면 긴 문장이 라벨 뒤에서 접혀 카드마다 시작점이 흐트러진다:

```
대상
- 일본어를 처음 접하는 분
```

글머리표는 **CSS `::before`로** 넣는다 — 실제 문자로 쓰면 낭독기가 "대시"라고 읽는다.

### 19-6. 덜어내는 것도 디자인이다

> *"코스 0 · 문자 이거 없애줘"* / *"숫자없이 입문 왕초보 … 만 있으면 될듯"*

같은 정보를 두 번 말하지 않는다. 코스 이름이 이미 순서를 말하고 있으면 **번호와 레벨 줄은 군더더기다.**

⚠️ **덜어낼 때 접근성을 함께 본다.** 눈에서 지우는 것과 화면에서 없애는 것은 다르다:

| 대상 | 처리 | 이유 |
|---|---|---|
| `aria-hidden` 이 이미 붙은 장식 | `display: none` | 낭독기가 **원래 안 읽었다** — 잃는 것이 없다 |
| 화면에만 안 보이면 되는 정보 | **시각적 숨김**(`.k-sr` 방식) | 지우면 낭독기 사용자가 그 정보를 통째로 잃는다 |

### 19-7. ⚠️ 면을 칠하면 그 위에 얹힌 것을 전부 다시 본다

**가장 값비싼 교훈이다.** 카드 배경을 흰색 → 회색으로 바꾸는 **한 줄** 때문에 같은 색을 쓰던 것들이 한꺼번에 사라질 뻔했다:

| 요소 | 그대로 뒀다면 |
|---|---|
| 진도 막대 트랙 | 빈 구간이 묻혀 **채운 부분만 떠 보임** |
| 중립 배지 | **통째로 사라짐** |
| 비활성 카드 | 일반 카드와 **구별 불가** |
| 카드 속 안내 알약 | **통째로 사라짐** |
| 흐린 회색 글자 | 대비 **약 2:1** — 배경과 같은 색 |

> **사라지는 것은 에러를 내지 않는다.** 테스트도 콘솔도 조용하다.
> 면을 바꾼 뒤 **그 면 위의 모든 색을 눈으로 훑는 것**이 절차의 일부다.

**지금 화면에 안 나오는 조합도 미리 막는다** — 안내 알약은 그것을 가진 코스가 한 장뿐이라 우연히 안 겹쳤을 뿐이다.

### 19-8. 새 화면에 적용할 때 — 체크리스트

- [ ] **읽어야 할 글이 가장 크고 진한가?** 제목 > 내용 > 라벨 순으로 벌어졌나(§19-2)
- [ ] 굵기를 **제목에만** 썼나
- [ ] 보조 텍스트가 `--muted2`가 아니라 **`--muted`** 인가
- [ ] 카드·패널이 **페이지 배경과 다른 면**인가(§19-3)
- [ ] 면을 칠했다면 **그 위 요소의 색을 전부 확인**했나(§19-7)
- [ ] 같은 종류 중 **한 장만 튀지** 않는가(§19-4)
- [ ] 강조 수단이 **하나뿐**인가. hover 값과 겹치지 않는가
- [ ] 길이가 다른 글 아래 요소가 **같은 높이**에 놓이는가(§19-5)
- [ ] 아이콘·글리프가 옆 글과 **높이가 맞는가**
- [ ] 헤더·본문의 **왼쪽 선이 맞는가**
- [ ] 같은 정보를 **두 번 말하고** 있지 않은가(§19-6)
- [ ] 무언가를 감췄다면 **낭독기는 여전히 읽는가**
- [ ] 새로 쓴 토큰이 `tokens.css`에 **실재하는가** — 없는 이름을 써도 CSS는 알려주지 않는다
- [ ] 이유가 사라진 규칙을 **남겨 두지** 않았나

### 19-9. 요구는 해법 형태로 온다 — 원인을 먼저 잰다

지적 9건 중 **셋은 첫 진단이 틀렸다.** 말한 대로 실행했다면 더 나빠졌다:

| 말한 것 | 그대로 했다면 | 실제 원인 |
|---|---|---|
| "글씨체 전부 굵은고딕으로" | 전부 굵게 → **위계 소멸**(실제로 겪었다) | 크기·대비가 뒤집힘 |
| "높낮이가 안 맞음" | 글자 크기 조정 | 가변 영역 미확보 |
| "배경이 같은 흰색" | 테두리만 진하게 | **면 색**을 달라는 것 |

**증상을 그대로 실행하기 전에 원인을 재 본다.** 특히 해법 형태로 오는 요청일수록,
그 해법이 진짜 원인을 겨냥하는지 먼저 확인한다.
