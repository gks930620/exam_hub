> 데이터 관련 문서는 전부 이 폴더에 있다. **여기부터 읽고 필요한 것만 파고들면 된다.**
>
> 갱신 2026-08-10 (큐넷 API 호출 전략 확정 — 실측으로 막힌 곳이 풀렸다).

## 3. 큐넷 — 막혀 있던 곳이 풀렸다 (2026-08-10 실측)

**전에 알던 것**: "`jmCd` 없이 부르면 `resultCode 930`. 종목별로 613콜인데 개발계정은 일 1,000회라 위험."

**실제로 확인한 것**:

- `930` 은 jmCd 와 **무관**했다. 실제 뜻은 **"한 페이지당 50개를 넘을 수 없습니다"** — `numOfRows` 문제였다.
- 종목 목록은 **1콜로 613종 전부** 받아진다(`jmcd`·종목명·직무분야·자격구분 포함, 응답 190KB).
- 일정은 `jmCd` 를 붙이면 **그 종목의 정확한 회차 일정**이 나온다.
  `jmCd` 없이 부르면 등급 단위 회차(`국가기술자격 기사 (2026년도 제3회)`)만 나오고,
  **국가전문자격은 자격명조차 없어**(`전문자격 (2026년도 26회 필기)`) 종목에 붙일 수 없다.

**호출 예산 — 하루에 한 번이면 되지만, 여유가 없다**

```
종목 목록        1콜   (연 1회면 충분, 종목은 거의 안 바뀐다)
종목별 일정    613콜   (1회 전량 갱신)
개발계정 한도  1,000콜/일
```

> ⚠️ **한 번 돌리면 하루 예산의 2/3를 쓴다.** 재시작 두 번이면 넘긴다 —
> 실제로 넘겨서 613콜이 전부 **429 LIMITED_NUMBER_OF_SERVICE_REQUESTS** 로 돌아온 적이 있다(2026-08-10).
> 그래서 두 가지를 코드에 넣었다:
> - **기동 시 수집은 큐넷을 켜면 자동으로 안 돈다**(`collect.on-startup` 을 비워 두면 그렇게 동작).
>   실 수집은 05:00 스케줄러가 한다. 지금 받아야 하면 `--collect.on-startup=true`.
> - **첫 429 에서 즉시 중단**한다. 한도를 넘긴 뒤 계속 두드리면 낭비이고 키가 막힐 수 있다.
>   받은 것까지는 반영되고, 다음 날 이어서 받는다.
>
> 운영에서는 **운영계정 증량 신청**을 해 두는 게 맞다.

실측 예 (정보처리기사 `jmCd=1320`, 2026년):

| 회차 | 필기접수 | 필기시험 | 실기접수 |
|---|---|---|---|
| 3회 | 07-20 ~ 07-23 | 08-07 | 09-21 |
| 2회 | 04-20 ~ 04-23 | 05-09 | 06-22 |

> ⚠️ **한 회차에 행이 두 개** 올 때가 있다(위 3회는 `0720~0723` 과 `0801~0802` 둘 다).
> 일반접수와 빈자리접수로 보인다. **접수 시작이 이른 행을 쓰도록 구현했다**
> (`dedupeByEarliestRegistration`) — 원서접수는 시작하자마자 마감되는 일이 흔해서,
> 늦은 접수일만 보여주면 사용자가 첫 기회를 놓친다. 버린 행은 로그로 남는다.

> ⚠️ **종목목록 XML 은 반드시 바이트로 받아 UTF-8 로 디코딩해야 한다.**
> 이 엔드포인트는 Content-Type 에 charset 을 안 줘서 스프링이 ISO-8859-1 로 읽는다.
> 그러면 종목명이 전부 깨지고("가스기술사" → "ê°ì¤..."), **깨진 이름이 기존 종목과 매칭되지 않아
> 같은 시험이 하나 더 생긴다.** 실제로 겪었고 지금은 고쳤다.

함정과 원본 응답은 [큐넷_API/](큐넷_API/) — `0_결론_어떤_API를_쓰나.md` 부터.

## 로컬에서 일정이 매번 사라지는 문제 (스냅샷 시드)

로컬 DB 는 **인메모리**라 서버를 끄면 수집한 1,500여 건이 사라진다. 그렇다고 켤 때마다 실 API 를
부르면 **613콜**이라 하루 한도(1,000)를 금방 넘긴다 — 재시작 몇 번에 한도를 태워 그날 아무것도
못 받은 적이 있다.

그래서 **한 번 받은 결과를 파일로 떠 두고** 기동할 때 그대로 얹는다.

| 파일 | 역할 |
|---|---|
| `seed/qnet_schedules.json` | 큐넷 일정 스냅샷. 없으면 조용히 건너뛴다 |
| `QnetSeedScheduleSource` | 그 파일을 읽는 수집 소스(`@Profile("!prod")`) |
| `AdminSeedExportController` | 지금 DB 에 있는 걸 시드 형식으로 내보낸다 |

### 스냅샷 새로 뜨는 법 (한도가 남아 있을 때)

```powershell
# 1) 실 API 로 한 번 받는다 (613콜 — 하루 한 번만)
./gradlew bootRun --args="--collect.on-startup=true"

# 2) 뜬 서버에서 시드로 내보낸다 (매니저 토큰 필요)
TOKEN=$(curl -s -X POST http://localhost:8081/api/manager/login \
  -H "Content-Type: application/json" \
  -d '{"username":"manager","password":"pass1234"}' | sed -E 's/.*"token":"([^"]*)".*/\1/')
curl -s -H "Authorization: Bearer $TOKEN" \
  http://localhost:8081/api/admin/export/qnet-schedules \
  -o src/main/resources/seed/qnet_schedules.json
```

이후로는 `./gradlew bootRun` 만 해도 일정이 붙는다.

> ⚠️ **스냅샷은 낡는다.** 시행처가 일정을 바꾸면 파일은 그대로다.
> 실 수집이 돌면 같은 `(시험, 연도, 회차, 구분)` 키를 덮어쓰므로 실데이터가 이긴다.
> **운영에서는 이 시드를 안 쓴다** — 매일 05:00 에 실 API 가 받아온다.

> ⚠️ 종목코드가 **숫자 4자리(jmCd)** 인 시험만 담는다. 어학·상의·KCA 는 각자 스크래퍼가
> 매번 받아오므로 스냅샷에 넣지 않는다(넣으면 낡은 값이 실데이터를 가릴 수 있다).
