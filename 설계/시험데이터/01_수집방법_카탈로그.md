시험 일정 데이터 ──┼─ ② 스크래핑 ──── 어학·민간자격 ....... 사이트마다 어댑터 1개

## 1. 큐넷 — 어떤 데이터를 주나

**국가기술자격 513종 + 국가전문자격 100종 = 613종.** 유일하게 공식 API가 있고, 무료다.

### 1-1. 쓰는 API 4개 (+선택 1개)

모든 조회가 **`jmCd`(종목코드) 하나**를 키로 돈다. 상세는 [큐넷_API/0_결론](큐넷_API/0_결론_어떤_API를_쓰나.md).

| # | API | 주는 데이터 | 우리 쓰임 |
|:-:|---|---|---|
| **2** | 종목 목록 `InquiryListNationalQualifcationSVC/getList` | 613종의 `jmCd`·종목명·계열·직무분야·자격구분 | `Certificate` 마스터 시드. 검색의 근간 |
| **1** | 시험일정 `qualExamSchd/getQualExamSchdList` | **원서접수 시작/마감, 시험일, 합격발표일** (회차별) | **`ExamSchedule` = 이 앱의 존재 이유.** D-day·알림이 전부 여기서 나옴 |
| **3** | 응시수수료 `InquiryTestInformationNTQSVC/getFeeList` | 필기/실기 응시료 | 상세 화면 "얼마인가" |
| **5** | 종목별 자격정보 `InquiryInformationTradeNTQSVC/getList` | 시험과목·검정방법·합격기준·출제경향 | 상세 화면 "뭘 평가하고 어떻게 붙나" |
| 4 | 통계 `InquiryStatSVC` | 합격률·응시자수 | (선택) 경쟁률 뱃지. 연 1회 갱신이라 나중에 |

### 1-2. 실제 호출 예 (정보처리기사 `jmCd=1320`)

```
[배치 1회] 종목 마스터 613종
  GET http://openapi.q-net.or.kr/api/service/rest/InquiryListNationalQualifcationSVC/getList

[종목별] 시험일정  ← 핵심
  GET https://apis.data.go.kr/B490007/qualExamSchd/getQualExamSchdList
      ?dataFormat=json&implYy=2026&qualgbCd=T&jmCd=1320&numOfRows=50&pageNo=1
```

### 1-3. 큐넷의 함정 (실측으로 확인된 것)

- **`openapi.q-net.or.kr` 는 HTTPS 가 안 된다** — HTTP 로만 호출된다(HTTPS 는 타임아웃). `apis.data.go.kr` 는 HTTPS 정상.
- **인증키는 Encoding/Decoding 두 벌**이 발급된다. URI 를 직접 조립하므로 **Encoding 키**를 써야 한다.
- **개발계정은 일 1,000 호출 제한.** 613종 × 여러 API 를 매일 돌리면 초과한다 → 운영계정 증량 신청 필요, 또는 일정 API(1번)만 매일·나머지는 주 1회.
- **컴활·워드프로세서는 큐넷 API 에 안 잡힐 수 있다** — 국가기술자격이지만 **시행처가 대한상공회의소**다(§3-1). 실측 확인 후 안 잡히면 별도 스크래핑.
- **정보보안기사**도 국가기술자격이나 **시행처가 KCA**다(§3-1).

어학은 **공공 API가 사실상 없다.** 시행처 사이트의 "시험일정" 페이지가 원본이다.

```
[큐넷 API]        ─┐
[사이트 스크래퍼]  ─┼─→ ScheduleSource → CollectedSchedule(정규화)
[관리자 수기입력]  ─┘        → DiffService → Certificate + ExamSchedule + 알림예약
```

- **소스 하나 추가 = `ScheduleSource` 구현 1개 추가.** DB·API·화면은 손대지 않는다.
- 이미 있는 구현: `QnetApiScheduleSource`(API), `SeedFileScheduleSource`(JSON 시드), `MockScheduleSource`(개발용).
- 구현됨(2026-09 기준): `KorchamScheduleSource`·`KcaScheduleSource`·`DataqScheduleSource`·`KuksiwonScheduleSource`·`TopikScheduleSource`·`YbmScheduleSource`(YBM 어학 7종)·`KofiaScheduleSource`(금융투자협회 9종)·`KbiScheduleSource`(금융연수원 8종)·`KspoScheduleSource`(체육공단 4종, 급수별)·`HanjaScheduleSource`·`KicpaScheduleSource`·`FlexScheduleSource`·`FssCpaScheduleSource`·`HanjaScheduleSource`(어문회 4종)·`KicpaScheduleSource`(AT 4종)·`FlexScheduleSource`(FLEX 7종)·`FssCpaScheduleSource`(공인회계사)·`KpcScheduleSource`(생산성본부 12종)·`Teps`·`Jlpt` + 파일 소스 `SeedFileScheduleSource`·`SnapshotScheduleSource`. 수기 입력은 소스가 아니라 `AdminScheduleController`(`/api/admin/schedules`, 매니저 모달)로 들어온다.

### 4-2. 단계별 계획

| 단계 | 할 일 | 얻는 것 | 막는 것 |
|---|---|---|---|
| ✅ **1. 큐넷 켜기** | `QNET_API_KEY` + `QNET_API_ENABLED=true` | **613종** | 완료(2026-08-28) |
| ✅ **2. 관리자 수기 입력** | `/admin` 할 일 → [넣기] 모달(`AdminScheduleController`) | 공무원·한능검 등 **수기 63종** | 화면 완료 — 채우는 건 사람 |
| **3. 스크래퍼 2개** | 대한상공회의소(컴활) → dataq(SQLD·ADsP) | 수험 인구 최다 구간 | 없음 |
| **4. 스크래퍼 확장** | KPC·KCA·금융협회·YBM(토익) | 커버리지 확대 | 사이트별 구조 파악 |

> **2단계를 3단계보다 먼저 두는 이유**: 수기 입력 틀은 어차피 `PENDING_REVIEW` 승인 화면으로도 필요하다.
> 한 번 만들면 "스크래퍼 없는 모든 시험"을 즉시 편입할 수 있어 투자 대비 회수가 가장 빠르다.

### 4-3. 지금 시드에 있는 `approx` 를 어떻게 없애나

현재 52종 중 50종이 추정 날짜다. 이건 **로컬 데모용**(`@Profile("!prod")`)이라 운영에 안 나가지만,
운영을 켜려면 소스별로 실데이터로 바꿔야 한다.

| 시드 분류 | 교체 경로 |
|---|---|
| 공무원 5종 | 2단계 수기 입력 (연 1회, 전년 공고) |
| 어학 13종 | TOEIC·TEPS·JPT·HSK 는 3~4단계 스크래퍼 / JLPT 는 수기 |
| 사무·IT 13종 | 컴활·워드 → 상공회의소 스크래퍼 / ADsP·SQLD → dataq 스크래퍼 |
| 금융·회계 10종 | 4단계 스크래퍼 (연 2~4회라 수기도 가능) |
| 한국사·한자 4종 | 수기 (한능검은 스크래핑도 검증됨) |

### 4-4. 데이터 신뢰 표시 (제품 차원)

추정 데이터를 확정처럼 보여주면 "마감을 놓치지 않게" 해준다는 약속을 스스로 어긴다.

- `ExamSchedule` 에 **출처 구분**을 노출한다 — 공식 API / 시행처 확인 / 추정.
- 추정 데이터는 화면에 **"시행처 확인 필요"** 를 붙이고, 알림도 "예정"으로 문구를 낮춘다.
- 모든 상세에 **원문 URL + 수집 시각**을 병기한다(이미 구현됨).

### 4-5. 스크래핑 가드레일

- **사실(날짜)만 저장.** 설명 문구·표·디자인은 복제하지 않는다.
- **출처 URL·수집시각 병기** + "최종 확인은 시행처에서" 고지.
- **봇 매너**: robots.txt 존중, 요청 간 지연, **일 1회** 이하. 사용자 요청마다 긁지 않는다(배치로 DB 적재).
- **공공기관 우선**(한능검·TOPIK·공무원) — 공공누리 대상이라 위험이 낮다.
- **한 사이트 전체를 통째로 재현하지 않는다** — 우리는 여러 소스의 큐레이션이지 특정 사이트의 복제가 아니다.
