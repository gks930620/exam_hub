# 1번. 국가자격 시험일정 조회 서비스 (qualExamSchd)

| 항목 | 값 |
|---|---|
| 데이터명 | 한국산업인력공단_국가자격 시험일정 조회 서비스 |
| End Point | `https://apis.data.go.kr/B490007/qualExamSchd` |
| 오퍼레이션 | `/getQualExamSchdList` (1개) |
| 포맷 | JSON / XML (`dataFormat`로 선택) |
| 프로토콜 | **HTTPS OK**, 파라미터명 `serviceKey`(소문자) |
| 갱신주기 | 월 1회 |
| 활용기간 | 2026-07-28 ~ 2028-07-28 |
| 상태 | ✅ 실제 호출 성공 |

이 API의 강점: **국가기술(T)·전문(S)·과정평가형(C)·일학습병행(W) 전 자격구분을 한 번에** 커버.
약점: **종목명이 없다**(jmCd로만 구분, description은 등급 텍스트). 종목명은 [2번](2_국가자격_종목목록.md)으로 조인.

---

## 요청 파라미터

| 파라미터 | 필수 | 설명 | 예 |
|---|:--:|---|---|
| `serviceKey` | ★ | 발급 인증키(Encoding) | `{SERVICE_KEY}` |
| `implYy` | ★ | 시행년도 | `2026` |
| `numOfRows` | ★ | 페이지 결과 수 (**최대 50**, 초과 시 resultCode 930) | `50` |
| `pageNo` | ★ | 페이지 번호 | `1` |
| `dataFormat` | ★ | `xml` / `json` (대소문자 무관) | `json` |
| `qualgbCd` | 옵션 | 자격구분 `T`=국가기술 `S`=국가전문 `C`=과정평가형 `W`=일학습병행 | `T` |
| `jmCd` | 옵션 | 종목코드(2번 마스터의 jmcd) | `1320`=정보처리기사 |

**호출 예:**
```
https://apis.data.go.kr/B490007/qualExamSchd/getQualExamSchdList?serviceKey={SERVICE_KEY}&dataFormat=json&implYy=2026&qualgbCd=T&jmCd=1320&numOfRows=50&pageNo=1
```

## 응답 필드 (item 1건 = 시행회차 1건)

| 필드 | 설명 | 형식 |
|---|---|---|
| `implYy` | 시행년도 | `2026` |
| `implSeq` | 시행회차 | 정수 |
| `qualgbCd` / `qualgbNm` | 자격구분 코드/명 | `T` / `국가기술자격` |
| `description` | 시행계획 설명(등급+회차) | `국가기술자격 기사 (2026년도 제3회)` |
| `docRegStartDt` / `docRegEndDt` | **필기 원서접수** 시작/종료 | `yyyyMMdd` 문자열 |
| `docExamStartDt` / `docExamEndDt` | 필기시험 시작/종료 | 〃 |
| `docPassDt` | 필기 합격발표 | 〃 |
| `pracRegStartDt` / `pracRegEndDt` | **실기/면접 원서접수** 시작/종료 | 〃 |
| `pracExamStartDt` / `pracExamEndDt` | 실기/면접 시작/종료 | 〃 |
| `pracPassDt` | 실기/면접 합격발표 | 〃 |
| `totalCount` / `numOfRows` / `pageNo` | 페이징 메타 | 정수 |

> - **빈 값은 `""`**(JSON) / 빈 태그(XML). 기능사는 필기 CBT 상시라 `docExam*`가 비고 접수/발표만 오는 식으로 필드가 선택적으로 빈다.
> - **국가전문자격(S)은 실기(작업형) 개념이 없음** → `prac*`가 비거나 면접 일정만.

## 실측 결과 (2026년, 실제 호출)

**자격구분별 2026 시행회차 수** (`implYy=2026`, `numOfRows=50`):

| qualgbCd | 자격구분 | totalCount |
|:--:|---|:--:|
| T | 국가기술자격 | 74 |
| S | 국가전문자격 | 76 |
| C | 과정평가형자격 | 4 |
| W | 일학습병행자격 | 3 |

**⚠️ 중복 행 발견 (중요)** — `jmCd=1320`(정보처리기사) 조회 시 `totalCount=6`인데, **회차 3개 × 2행**이었다:

| implSeq | docRegStart~End | 해석 |
|:--:|---|---|
| 3 | 2026-07-20 ~ 07-23 | 정기(일반) 접수 |
| 3 | 2026-08-01 ~ 08-02 | 추가/빈자리 접수 (같은 회차, 시험일 동일) |
| 2 | 2026-04-20 ~ 04-23 | 정기 |
| 2 | 2026-05-03 ~ 05-04 | 추가 |
| 1 | 2026-01-12 ~ 01-15 | 정기 |
| 1 | 2026-01-24 ~ 01-25 | 추가 |

→ **dedup/저장 키를 `(jmCd, implSeq, docRegStartDt)` 조합**으로 잡아야 한 회차가 접수기간별로 분리 저장된다. 접수 알림도 이 두 접수기간 각각에 걸어야 함(정기 놓쳐도 추가접수 알림 가능 → 오히려 제품 가치).

- 원본 응답: `samples/시험일정_2026_정보처리기사.json`, `samples/시험일정_2026_기술자격_p1.json` 등.

## 에러 코드 (헤더 resultCode)

| 코드 | 의미 |
|---|---|
| `00` | 정상 |
| `10` | 잘못된 요청 파라미터 |
| `20` | 서비스 접근거부 | 
| `22` | 요청제한 초과 |
| `30` / `31` | 미등록/만료 서비스키 |
| `900` | 포털↔HRDK 게이트웨이 인증 오류 |
| `910` | 필수 파라미터 누락 |
| `920` | dataFormat 오류(json/xml만) |
| `930` | **페이지당 최대(50) 초과** |
| `990` | HRDK 서버 에러 |
