## 0. 인증키 · 공통 규칙 (먼저 읽기)

- **인증키는 1개로 전 서비스 공용.** 공공데이터포털에서 발급한 키 하나로 아래 서비스를 모두 호출한다.
- 문서 예시의 `{SERVICE_KEY}` 자리에 인증키를 넣는다. 실제 키는 **`.env`의 `QNET_API_KEY`** 에 두고 커밋/문서에 원문을 남기지 않는다.
- **⚠️ Encoding 키 vs Decoding 키 (이중 인코딩 함정 — Java 구현 시 핵심):**
  - URL 쿼리스트링에 **문자열로 직접 붙일 때** → **Encoding 키**(이미 `%2F` 등으로 인코딩됨) 사용.
  - `RestTemplate`/`UriComponentsBuilder`/`WebClient` 처럼 **클라이언트가 파라미터를 자동 인코딩**하면 → **Decoding 키**를 넘겨야 한다(안 그러면 `%`가 또 인코딩돼 `SERVICE_KEY_IS_NOT_REGISTERED`(30) 발생). `UriComponentsBuilder`는 `build(true)`로 인코딩 통제.
  - 즉 "어느 키가 맞냐"는 **HTTP 클라이언트가 자동 인코딩하느냐**에 달렸다. 어댑터 구현 시 이 지점을 반드시 테스트.
- **호스트가 두 종류이고 프로토콜이 다르다 (실측 확인):**

| 호스트 | 프로토콜 | 파라미터명 | 해당 API |
|---|---|---|---|
| `apis.data.go.kr/B490007/...` (포털 게이트웨이) | **HTTPS OK** | `serviceKey` (소문자 s) | 1번 시험일정 |
| `openapi.q-net.or.kr/api/service/rest/...` (큐넷 직접) | **HTTPS 연결 안 됨 → HTTP만 200** | `ServiceKey` (대문자 S) | 2·3번, 그 외 q-net 직접 서비스 |

  > ⚠️ `openapi.q-net.or.kr`는 포털 문서에 `https://`로 적혀 있지만 **443 연결이 타임아웃**된다. 반드시 `http://`로 호출할 것. 구현 시 어댑터에서 호스트별로 스킴을 분기.

- **응답 포맷**: 1번은 XML/JSON 선택(`dataFormat`), 2·3번은 **XML 전용**.
- **에러는 헤더로**: HTTP 200이어도 `<resultCode>`가 `00`이 아니면 실패(예: `930` 페이지 초과). 파싱 전에 resultCode 확인 필수.
- **개발계정 트래픽**: 오퍼레이션당 1,000회/일. 운영계정 전환으로 증량.

## 2. API 간 관계 — 어떻게 조합하나 (핵심)

세 API가 **`jmCd`(종목코드)** 로 연결된다. 이게 우리 DB의 `certificate.source_code` = diff 매칭 키가 된다(설계 04와 정합).

```
[2번 종목목록]  jmCd → 종목명/계열/직무분야   ── 자격증 마스터(certificate 시드)
     │  jmCd
     ├──────────────► [1번 시험일정]  jmCd로 필터 → 회차별 접수/시험/발표일
     │                 (국가기술+전문+과정평가+일학습 전 구분 커버, 단 종목명 없음)
     └──────────────► [3번 종목별시험정보]  jmCd → 종목별 회차 일정 + 응시수수료 + 서류제출기간
                       (국가기술자격만, 대신 필드가 더 풍부 + 종목명 포함)
```

**1번 vs 3번(둘 다 국가기술자격 일정) — 무엇을 쓰나:**

| 항목 | 1번 getQualExamSchdList | 3번 getJMList(종목별) |
|---|---|---|
| 커버 자격구분 | 기술(T)/전문(S)/과정평가(C)/일학습(W) **전부** | 국가기술자격 **만** |
| 종목명 포함 | ❌ (jmCd로만 구분, description은 등급 텍스트) | ✅ `jmfldnm` 직접 포함 |
| 서류제출 기간 | ❌ | ✅ `docsubmit*` |
| 응시수수료 | ❌ | ✅ (getFeeList 별도 오퍼레이션) |
| 임박 회차 텍스트 | `description`("...기사 2026년도 제3회") | `implplannm`("2026년 정기 기사 2회") |
| 호스트/프로토콜 | HTTPS, JSON 가능(파싱 쉬움) | HTTP, XML만 |

→ **권장**: 국가기술자격은 **3번(getJMList)** 로 종목별 상세를(수수료·서류제출 포함), 국가전문자격·과정평가·일학습은 **1번**으로 수집. 종목명은 **2번**을 마스터로 조인.

## 3. 앱 관점 결론 (5개 API 역할 배분)

| 우리 DB / 화면 | 1순위 소스 | 보조 |
|---|---|---|
| **certificate 마스터** | **2번**(613종: 기술 513+전문 100) `jmcd/jmfldnm/seriesnm/직무분야` | — |
| **exam_schedule (기술자격)** | **3번 getJMList**(종목별, 수수료·서류제출 포함, 단 현재연도만) | **1번**(과거연도·과정평가·일학습) |
| **exam_schedule (전문자격)** | **1번**(qualgbCd=S + jmCd, 세무사·공인중개사 검증완료) | — |
| **cert 상세 — 시험과목/검정방법/합격기준/출제경향** | **5번**(jmCd, 안정적) | — |
| **cert 상세 — 응시수수료** | **3번 getFeeList** | — |
| **cert 상세 — 합격률/응시자(경쟁률 뱃지)** | **4번 통계**(연1회, 후순위) | — |

핵심 주의:
- **모든 조인 키 = `jmCd`(종목).** 이걸 `certificate.source_code`로 저장 → diff 멱등 매칭(설계 04 정합).
- **중복 행**: 같은 회차가 접수기간만 다른 여러 행(정기 vs 추가접수). dedup 키 `(jmCd, 회차, docRegStartDt)`. → [1번 §실측](1_국가자격_시험일정조회.md).
- **갱신주기**: 일정 원천 월 1회 → 수집 배치 일 1회 충분. 통계는 연 1회 → 성공 시 장기 캐시.
- **재시도 필수**: openapi.q-net.or.kr는 간헐적 99 오류.
