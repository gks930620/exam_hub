**호출 예:**

## 응답 필드 (item = 정보구분 1건 → **한 종목에 여러 item**)

| 필드 | 설명 | 비고 |
|---|---|---|
| `jmfldnm` | 종목명 | |
| `infogb` | 정보구분 | **1..n** — 종목마다 여러 개 (아래) |
| `contents` | 내용 | 최대 **4000자**, 옵션(빌 수 있음). 비정형 원문 텍스트 |
| `obligfldcd/nm`, `mdobligfldcd/nm` | 대/중 직무분야 | zero-padding |

> **핵심**: 한 종목을 조회해도 `infogb`별로 여러 item이 온다. `contents`는 `① 시행처 : … ② 관련학과 : … ③ 시험과목 : … ④ 검정방법 … ⑤ 합격기준 : …` 형태의 **원문 한 덩어리**라, 항목별로 쓰려면 원문자(①~⑤) 기준 파싱 필요.

## 실측 결과 (실제 호출, jmCd=1320 정보처리기사)

- `resultCode=00`, **item 3건** 반환. `infogb` 값: **`출제경향`, `출제기준`, `취득방법`** (가이드엔 출제경향/취득방법만 예시였으나 실제로는 `출제기준`도 옴 → enum 하드코딩 금지 확인).
- 응답 크기 3,859 bytes로 작고 즉시 응답(안정적).
- 원본: `samples/종목별자격정보_정보처리기사_jmCd1320.xml`

## getFeeList와의 관계

`jmfldnm`/`infogb`/`contents`/직무분야 4필드로 **응답 구조가 [3번](3_국가기술자격_종목별시험정보.md) getFeeList와 사실상 동일**. 하나의 "종목 상세정보" 테이블로 합쳐 `infogb`를 구분값으로 저장하는 설계가 자연스럽다.

| API | infogb 값 | contents |
|---|---|---|
| 3번 getFeeList | `응시 수수료` | `1차 : 19400, 2차 : 22600` |
| **5번 (이 API)** | `출제경향`·`출제기준`·`취득방법` | 자격 안내 원문(≤4000자) |

## 구현 체크포인트

- `jmCd` 단위 조회 → 종목 순회하며 수집(2번 jmcd 목록 사용). 자격 서술정보의 1순위 소스.
- `infogb`는 1..n, `contents`는 nullable + 4000자 → CLOB/대용량 컬럼.
- `resultCode == "00"` 만 정상. 코드필드 zero-padding 문자열.
